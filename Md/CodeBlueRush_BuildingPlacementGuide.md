# CodeBlueRush 전체 건물 배치 가이드 — WebGL 모바일 최적화 리뉴얼

> 기준 프로젝트: Unity 6000.3.23f1 / 2D / WebGL / 모바일 / 480×854
>
> 최우선 제약: **최종 웹사이트 배포 용량은 절대로 100 MB를 초과하지 않는다**
>
> 작업 우선순위:
>
> **1순위 용량 제한 → 2순위 연산 최적화 → 3순위 구현 완료**
>
> 기존 건물 배치 성격은 유지하되, 건물 종류와 이미지 제작 수는 적극적으로 재사용 가능한 구조로 축소한다.

---

# 1. 절대 목표

건물은 도시를 풍부하게 보이게 해야 하지만,
각 건물마다 새로운 대형 PNG를 추가하는 방식은 사용하지 않는다.

최종 목표:

- 적은 원본 Sprite
- 높은 재사용률
- 작은 빌드 크기
- 낮은 Draw/CPU 부담
- 구역별 시각적 차별성 유지

건물 다양성은 **텍스처 수 증가**보다 다음 방법으로 만든다.

- 회전
- 좌우 반전
- SpriteRenderer Color
- 작은 간판 Sprite 교체
- 나무 / 주차장 / 펜스 조합
- 배치 방향과 간격 변화

---

# 2. 용량 예산

최신 main의 현재 `docs/` 배포 크기는 약 **65.74 MB**이다.

100 MB까지 절대 남은 공간은 약 34.26 MB이지만,
안전한 내부 목표는 **85 MB 이하**로 둔다.

따라서 현재 기준 신규 콘텐츠의 안전한 전체 예산은 약 **19 MB** 수준이다.

권장 신규 예산 시작점:

| 항목 | 권장 최대 증가량 |
| --- | ---: |
| 도시 도로 / 인도 / 지형 | 4 MB |
| 건물 / 랜드마크 | **8 MB** |
| 식생 / 교통 소품 / 차량 / 시민 | 3 MB |
| 오디오 | 2 MB |
| 신규 Code / Shader / 기타 | 2 MB |

이 값은 실제 Release Build 결과를 기준으로 조정한다.

WebGL Player 최적화로 기본 빌드가 줄어든 경우에만 예산을 늘린다.

# 3. 전체 건물 배치 순서

항상 다음 순서를 유지한다.

```text
게임플레이 동선
↓
도로
↓
인도
↓
건물 배치 슬롯
↓
건물
↓
식생 / 주차장 / 펜스
↓
교통 소품
↓
작은 장식
```

건물 때문에 확정된 주행 동선을 변경하지 않는다.

---

# 4. 블록 단위 배치

건물을 임의 위치에 하나씩 놓지 않는다.

도로가 만든 공간을 블록으로 보고 배치한다.

```text
[도로]

[블록]
- 건물
- 주차장
- 나무
- 골목
- 빈 공간

[도로]
```

블록 전체를 건물로 100% 채우지 않는다.

상업지역도 건물 점유율은 약 70~80% 이하를 기본으로 한다.

---

# 5. 건물 크기 규격

기존 배치 슬롯 규격을 유지한다.

| 등급 | 기본 배치 슬롯 | 실제 건물 최대 권장 크기 | 주요 용도 |
| --- | ---: | ---: | --- |
| Small | 6 × 6 Unit | 약 5 × 5 Unit | 주택, 작은 상점, 관리소 |
| Medium | 10 × 8 Unit | 약 9 × 7 Unit | 빌라, 상가, 창고 |
| Large | 16 × 12 Unit | 약 15 × 11 Unit | 아파트, 공장, 오피스 |
| Landmark | 전용 | 20 × 20 Unit 이상 가능 | 병원, 소방서 등 |

건물 크기는 가능한 한 2 Unit 단위로 맞춘다.

---

# 6. 이미지 해상도 규칙

세계 크기가 크다고 Sprite 해상도를 크게 만들지 않는다.

실제 모바일 화면에서 보이는 픽셀 크기를 기준으로 한다.

기본 권장:

- Small 건물: 128~256 px
- Medium 건물: 256 px 중심
- Large 건물: 256~512 px
- Landmark: 512 px 중심
- Landmark 1024 px: 실제 화질 부족이 확인된 경우에만 허용
- 2048 / 4096 px 건물 이미지: 기본 금지

원본 이미지가 크더라도 Web Platform Override의 Max Size로 제한한다.

---

# 7. 건물 텍스처 제작 원칙

## 7.1 저용량 기본 원칙

- 한 건물 = Color Sprite 1장 원칙
- Normal Map 기본 금지
- Mask Map 기본 금지
- 별도 AO Map 기본 금지
- 별도 Shadow Texture 기본 금지
- 복잡한 Material 기본 금지

로우폴리 명암과 건물 그림자는 가능한 한 **기본 Sprite 자체에 Bake**한다.

동적 그림자가 필요한 차량 등에는 작은 공용 Blob Shadow Sprite를 사용한다.

---

## 7.2 투명 영역 최소화

건물 Sprite Canvas에 큰 투명 여백을 남기지 않는다.

실제 건물 실루엣에 가깝게 Crop한다.

투명 배경이 필요하지 않은 타일은 Alpha 없는 포맷을 사용한다.

---

## 7.3 Mipmap

고정 탑뷰 건물 Sprite는 기본적으로 Mipmap을 끈다.

카메라 줌 또는 축소에서 실제 품질 문제가 확인되는 리소스만 예외 처리한다.

---

## 7.4 Read/Write

런타임에서 Texture 픽셀 데이터를 읽을 필요가 없는 모든 건물 Texture는 Read/Write를 끈다.

---

## 7.5 Web 텍스처 압축

Web Platform Override를 사용한다.

우선순위:

1. 지원 기기 범위에서 가능하면 ASTC
2. 모바일 호환성이 더 필요하면 ETC2
3. ASTC 사용 시 8×8을 시작점으로 테스트

화질 문제가 없는 범위에서 큰 Block Size를 우선한다.

---

# 8. Sprite Atlas 규칙

건물 Sprite를 개별 Texture로 난립시키지 않는다.

권장 Atlas:

- `BuildingCommonAtlas`
- `BuildingLandmarkAtlas`
- `PropAtlas`

Atlas는 1024~2048 범위를 우선한다.

한 Sprite가 여러 Atlas에 중복 포함되지 않는다.

사용하지 않는 변형 Sprite까지 Atlas에 넣지 않는다.

---

# 9. 건물 다양성 제작 방식

새 PNG를 계속 추가하기 전에 다음 순서로 다양성을 만든다.

```text
1. 위치 변경
2. 회전 / 반전
3. Color Tint
4. 간판 Overlay 교체
5. 주변 소품 조합
6. 그래도 구분이 부족할 때만 새 Sprite 제작
```

예시:

편의점, 약국, 카페, 음식점을 모두 완전히 다른 건물 이미지로 만드는 대신,

```text
공용 Small Shop 건물
+
Convenience Sign
Pharmacy Sign
Cafe Sign
Restaurant Sign
```

방식으로 재사용할 수 있다.

# 10. 구역별 건물 리소스 최소 세트

기존 건물 종류의 기능은 유지하되,
실제 **고유 대형 Texture 수는 최소화**한다.

## 10.1 주거지역

필수 기본 Sprite:

- 단독주택 A
- 단독주택 B
- 빌라 A
- 소형 아파트
- 대형 아파트

다양성:

- 지붕 Tint
- 방향 변경
- 나무 / 차량 / 마당 조합

권장 고유 본체 Texture: **5개 내외**

랜드마크:

- 대형 아파트 단지

---

## 10.2 상업지역

필수 기본 Sprite:

- Small Shop 공용 본체
- 중형 상가
- 오피스
- 대형 상가

작은 Overlay:

- 편의점 간판
- 약국 간판
- 음식점 간판
- 카페 간판

권장 고유 본체 Texture: **4개 내외**

랜드마크:

- 중앙 광장 + 대형 상가

---

## 10.3 병원지역

필수 기본 Sprite:

- 종합병원 본관
- 응급센터
- 소형 의료/관리동
- 주차동

약국은 상업지역 Small Shop 본체를 재사용한다.

권장 고유 본체 Texture: **4개 내외**

랜드마크:

- 대형 종합병원

---

## 10.4 산업·항만지역

필수 기본 Sprite:

- 창고
- 공장
- 물류센터
- 사일로 / 탱크 세트

트럭 차고는 창고 또는 물류센터 변형을 우선 재사용한다.

권장 고유 본체 Texture: **4개 내외**

랜드마크:

- 대형 컨테이너 크레인

---

## 10.5 공원·하천지역

필수 기본 Sprite:

- 공용 관리소
- 작은 매점 / 카페
- 정자

화장실은 관리소 변형을 우선 사용한다.

권장 고유 본체 Texture: **3개 내외**

랜드마크:

- 호수 중앙 섬 + 정자

---

## 10.6 소방서지역

필수 기본 Sprite:

- 소방서 본관 + 차고
- 훈련 타워
- 관리/창고동

본관과 차고를 가능하면 하나의 랜드마크 세트로 묶는다.

권장 고유 본체 Texture: **3개 내외**

랜드마크:

- 소방서 본관 + 타워

# 11. 전체 고유 건물 Texture 상한

1차 목표:

- 일반 건물 본체: **약 20~24개 이하**
- 대형 랜드마크: **6개**
- 작은 간판/표시 Overlay: 필요한 만큼 사용하되 64~128 px 중심

새 건물을 추가하기 전에 기존 Sprite로 표현 가능한지 먼저 확인한다.

고유 Texture 개수가 증가한다고 게임성이 증가하지 않는다면 추가하지 않는다.

# 19. 건물 GameObject 연산 규칙

## 19.1 정적 건물에 MonoBehaviour를 붙이지 않는다

일반 건물은 기본적으로 다음만 가진다.

```text
Transform
SpriteRenderer
필요한 경우 단순 Collider2D
```

건물마다 Update / Start 로직을 만들지 않는다.

---

## 19.2 Material 공유

동일 계열 건물은 같은 Material을 사용한다.

색상 차이는 새 Material 생성보다 SpriteRenderer Color를 우선한다.

Runtime 중 `.material`을 호출하여 Material 인스턴스를 무분별하게 만들지 않는다.

---

## 19.3 Collider 단순화

- BoxCollider2D 우선
- 여러 복잡한 PolygonCollider2D 금지
- 지붕 돌출부 등 시각적 모양을 정확하게 따라가지 않아도 됨
- 구급차 주행에 필요한 충돌 범위만 표현

---

## 19.4 카메라 밖 정적 Sprite

SpriteRenderer 자체 렌더링은 카메라 Culling을 활용한다.

별도의 건물별 거리 체크 Update는 만들지 않는다.

필요하다면 **구역 Root 단위**로만 활성/비활성 관리한다.

---

# 20. 동적 오브젝트 최적화

건물 주변의 차량/시민 때문에 성능을 낭비하지 않는다.

다음은 Pool 기반으로 관리한다.

- 일반 차량
- 시민
- 이펙트

플레이어에서 멀리 떨어진 동적 오브젝트는 AI 및 Physics 실행을 중단한다.

상업지역처럼 밀도가 높은 지역도 전체 도시 NPC를 동시에 활성화하지 않는다.

---

# 21. 사용 금지 또는 제한 요소

용량과 모바일 WebGL 성능을 위해 기본적으로 제한한다.

- 건물별 2K / 4K Sprite
- 전체 구역을 한 장으로 만든 초대형 PNG
- 건물별 Normal Map
- 건물별 Mask Map
- 건물별 실시간 Light
- 건물별 실시간 Shadow
- 필요 없는 Particle
- 건물마다 다른 Material
- 동일 건물의 단순 색상 차이를 위한 별도 PNG
- 동일 방향 차이를 위한 별도 PNG
- 건물마다 Update
- 과도한 PolygonCollider2D

시각적 필요성이 명확하고 실제 Build/Profiler 테스트에서 예산 내임이 확인된 경우만 예외를 허용한다.

# 22. Reference 이미지 관리

기획 참고용 고해상도 이미지는 Runtime Build에 들어가지 않도록 관리한다.

권장:

- `Assets/Editor/References/`
- 또는 프로젝트 외부 참고자료 폴더

참고 이미지를 Scene, Prefab, Resources에서 직접 참조하지 않는다.

최종 게임에 쓰지 않는 대형 원본 이미지는 Player Build 대상에서 제외한다.

# 23. Resources 사용 원칙

도시 이미지 전체를 `Resources` 폴더에 넣지 않는다.

실제로 사용하지 않아도 Resources 폴더의 Asset 및 의존성이 빌드에 포함될 수 있으므로,
도시 리소스는 Scene/Prefab의 명확한 직접 참조를 기본으로 한다.

Addressables는 **총 웹사이트 용량을 줄이는 도구로 취급하지 않는다.**

필요한 경우 다음 목적에만 검토한다.

- 초기 다운로드 지연
- 메모리 사용량 감소
- 필요 시점 로드

동일한 100 MB 웹사이트 안에 모든 Addressable 파일을 같이 배포하면 총 배포 용량 자체는 줄지 않는다.

# 24. WebGL 빌드 최적화 공통 규칙

Release 기준:

- Development Build: Off
- Code Optimization: Disk Size with LTO
- Brotli Compression
- Data Caching: On
- Debug Symbols: Off
- Managed Stripping Level: High
- Strip Engine Code: On
- .NET Standard 2.1 우선
- Target WebAssembly 2023: 검증 후 On
- 불필요 Package / Plugin 삭제

현재 사용하지 않는 기능을 위해 대형 Package를 유지하지 않는다.

Package 제거는 한 번에 모두 하지 않고,
하나씩 제거 → 컴파일 → 파트 테스트 → Release Build 크기 비교 순서로 진행한다.

# 25. 건물 제작 단계별 용량 Gate

새 건물 파트를 만들 때 다음 순서를 사용한다.

```text
해당 구역 건물 전체 구현
↓
중복 Texture / Material 검사
↓
Atlas 적용
↓
Web Texture 압축 확인
↓
해당 구역 플레이 테스트
↓
Release WebGL Build
↓
Build Size 비교
```

용량이 예상보다 크게 증가하면:

```text
1. 해상도 감소
2. 중복 Sprite 통합
3. Tint / Overlay 방식으로 변경
4. 사용하지 않는 리소스 삭제
5. 필요하면 건물 종류 자체 축소
```

이 순서로 해결한다.

# 26. 완료 조건

건물 배치는 다음 조건을 모두 만족해야 완료다.

1. 6개 구역의 시각적 성격이 명확함
2. 기존 도로 동선을 침범하지 않음
3. 랜드마크 6개가 쉽게 구분됨
4. 일반 건물 Texture 수가 통제됨
5. 건물 Sprite가 Atlas/압축 규칙을 따름
6. 정적 건물에 불필요한 Script/Update가 없음
7. 모바일 WebGL에서 프레임 저하가 없음
8. Release Build 용량 증가량이 예산 내임
9. 전체 배포 크기가 100 MB 이하임

# 27. 최종 판단 우선순위

건물 리소스를 추가할 때 항상 다음 순서로 판단한다.

```text
1순위: 100 MB 제한을 안전하게 지키는가?
↓
2순위: 모바일 WebGL에서 CPU / GPU / Memory 부담이 낮은가?
↓
3순위: 요구한 건물과 구역 디자인을 구현할 수 있는가?
```

필요하다면:

- 건물 종류를 줄인다.
- 해상도를 낮춘다.
- Tint로 색상 변형을 만든다.
- 간판만 교체한다.
- 장식을 줄인다.

하지만 **100 MB 제한은 절대로 변경하지 않는다.**
