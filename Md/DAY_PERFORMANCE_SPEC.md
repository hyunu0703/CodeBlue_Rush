# 날짜 진행 및 실적 평가 기획

- 확정일: 2026-10-28
- 상태: 기획 확정 및 1단계 계산·진행 상태, 2단계 로컬 저장·Start 진입 구현·검증 완료. 3단계 이후는 미구현이다. [준비·1단계 결과](DAY_PERFORMANCE_STAGE1.md), [2단계 결과](DAY_PERFORMANCE_STAGE2.md)를 참고한다.
- 프로젝트 Unity 버전: 6000.3.23f1 (`ProjectSettings/ProjectVersion.txt` 확인)

## 1. 문서 목적과 적용 범위

기존 미션 흐름을 유지하면서 무제한 날짜 진행, 하루 실적, 매 5일 단위 실적 평가와 해고 후 재시작 규칙을 정의한다. 이번 단계의 완료 조건은 승인된 규칙을 문서화하고, 추후 조정할 점수와 기준 수치를 구분하는 것이다. 코드, 씬, 프리팹, 프로젝트 설정은 변경하지 않는다.

날짜, 실적, 결과 확인, 정기 평가 및 재시작에 관해서는 이 문서를 기존 `GAME_REMAKE_SPEC.md`와 `Md/MISSION_DISPATCH.md`보다 우선 적용한다. 다른 기능은 기존 기획과 구현을 따른다. 이 문서는 구현 착수 지시가 아니며, 실제 구현은 별도 요청에 따라 진행한다.

## 2. 핵심 방향

- 한 번의 플레이는 1일차부터 시작하며 일차 상한 없이 진행한다.
- 하루에 수행하는 미션은 하나로 고정한다.
- 기존 Waiting의 요청 확인, 미션 수락, 출동하기 흐름을 유지한다.
- 미션 선택지, 위험도 선택 등 새로운 선택 시스템은 추가하지 않는다.
- 기존 랜덤 시드 기반 맵 생성과 환자 픽업·병원 후송 흐름을 유지한다.
- 매일 후송 결과를 실적으로 환산하고 기록한다.
- 평가는 5일마다 수행하되, 1일차부터 현재까지의 누적 실적을 사용한다. 평가를 통과해도 실적을 초기화하거나 차감하지 않는다.
- 5·10·15일차처럼 매 5일을 마치고 6·11·16일차로 넘어갈 때 실적을 평가한다.
- 해당 평가의 목표 실적 이상이면 다음 일차로 계속 진행하고, 미달이면 해고된다. 평가 통과를 게임 클리어로 처리하지 않는다.
- 첫 5일 구간의 기준 요구량은 200점이며, 이후 각 구간 기준 요구량은 20점씩 증가한다. 평가 목표는 그 기준 요구량들을 합산한 누적 목표로, 200·420·660·920점 순서다. 목표 상한은 두지 않는다.
- 일차 자체에는 상한이 없지만, 목표가 계속 상승해 언젠가는 통과 불가능해지는 구조를 허용한다. 무한히 생존할 수 있음을 보장하는 기획은 아니다.
- 게임을 다시 켜면 해당 일차의 미션 수락 전 상태로 돌아가 그날을 다시 시작한다. 단, 정기 평가가 남아 있으면 평가를 먼저 표시하고, 해고 상태이면 해고 화면을 유지한다.
- 해고 후 재시작하면 이어받는 성장이나 해금 요소 없이 1일차부터 다시 시작한다.

### Start 화면과 저장 상태별 진입

- 기존 Start 화면과 `시작하기` 버튼을 유지한다. 별도의 새 게임·이어하기 버튼은 추가하지 않는다.
- `시작하기`를 누르면 저장 상태를 확인해 Waiting으로 진입하고 다음 규칙을 적용한다.

| 저장 상태 | Waiting 진입 후 처리 |
| --- | --- |
| 저장 없음 | 첫 구간 목표의 1일차 미션 수락 전 상태로 시작 |
| 일반 진행 | 저장된 일차의 미션 수락 전 상태로 복귀 |
| 정기 평가 대기 | 새 미션 요청 전에 정기 평가 화면 표시 |
| 해고 | 새 미션 요청 없이 해고 화면 표시 |
| 저장 데이터 읽기 실패 | 오류와 재시도 수단을 표시하고 정상적인 진행 상태를 확인할 때까지 Waiting 진입 보류 |

## 3. 하루의 시작과 종료

### 일반적인 하루 흐름

```text
현재 일차의 Waiting
→ 요청 확인 → 미션 수락 → 출동하기
→ GamePlay 진입 및 기존 랜덤 시드로 맵 생성
→ 환자 픽업 장소로 이동
→ 구출 컷신 및 환자 탑승
→ 병원까지 후송
→ 해당 일차의 결과 표시
→ `확인` 버튼으로 해당 일차 종료 및 당일 실적·다음 일차 저장
→ Waiting 복귀 시 자동으로 다음 일차 적용
→ 6·11·16일차 등이면 새 미션 요청 전에 누적 실적 평가
→ 일반 일차 또는 평가 통과 시 해당 일차의 미션 요청 대기
```

- 첫 Waiting 진입은 1일차다.
- 미션 수락, 출동, 환자 픽업만으로 날짜가 증가하지 않는다.
- 환자를 병원까지 후송하고 결과를 확인해야 해당 일차가 끝난다.
- 다음 일차로 진행하기 위한 별도의 날짜 선택이나 수동 변경은 없다.
- Waiting에서 기존 방식으로 요청을 거절하고 다시 기다리는 것은 미션 수행이나 하루 종료로 계산하지 않는다.
- 결과를 확인한 날에는 추가 미션을 수행하지 않는다.
- 단순한 씬 재진입 자체를 하루 완료로 취급하지 않는다.
- 5의 배수 일차를 마친 경우에는 실적 평가를 통과해야 다음 일차의 미션을 진행할 수 있다.

### 매 5일 종료 후 다음 일차 진입

```text
5일차 Waiting → 미션 수락·출동 → 환자 픽업 → 병원 후송
→ 5일차 결과 확인 → 6일차 진입 시 실적 평가
→ 목표 이상: 통과 안내 → `계속하기`
             → 누적 실적을 유지하고 다음 누적 목표를 저장·공개
             → 6일차 Waiting에서 새 미션 요청 대기
→ 목표 미달: 해고 상태 저장·안내 → `다시 시작` → 초기화 저장 → 1일차 Waiting

10일차 결과 확인 → 11일차 진입 시 실적 평가 → 통과 시 계속 진행
15일차 결과 확인 → 16일차 진입 시 실적 평가 → 통과 시 계속 진행
이후에도 같은 주기로 반복
```

매 5일 종료 후 다음 날로 넘어가는 경계에서 평가하며, 다음 날 미션을 수행한 뒤 평가하는 방식이 아니다. GamePlay에서 후송 결과를 확인한 뒤 Waiting으로 복귀한다. 6·11·16일차 Waiting에서는 새 미션 요청 전에 각각 1~5일·1~10일·1~15일의 누적 실적을 평가하고, 통과한 뒤에 그날의 요청을 받는다. 평가를 통과해도 일차를 1로 되돌리거나 실적을 초기화하지 않는다.

### Waiting의 실적 안내

- 각 5일 구간이 시작될 때 다음 평가에서 요구할 누적 목표를 공개한다.
- Waiting에서 현재 누적 실적, 다음 평가의 누적 목표, 목표 달성에 필요한 부족 실적을 표시한다.
- 부족 실적은 `max(0, 다음 평가의 누적 목표 - 현재 누적 실적)`으로 계산한다. 목표를 이미 달성하면 0으로 표시한다.
- 여기서 평가까지 남은 실적은 부족한 점수를 뜻하며, 남은 미션 수로 대체하지 않는다.
- 6·11·16일차 평가에서는 해당 평가까지의 누적 실적과 누적 목표를 먼저 보여준다. 통과 후에는 실적을 그대로 유지하고 다음 누적 목표를 안내한다.

## 4. 하루 결과에 기록할 항목

| 항목 | 기록 및 표시 규칙 |
| --- | --- |
| 일차 | 이번 결과가 속한 일차 |
| 환자 잔여 HP | 병원 인계 시점의 HP를 소수점 첫째 자리까지 내림 표시. 생존 중 0.1% 미만과 실제 HP 0은 구분 |
| 환자 상태 | 잔여 HP에 따른 안정·위험·위독, HP 0일 때 사망 |
| 사고 여부 | 해당 미션에서 다른 차량과 충돌했는지 표시 |
| 저속 충돌 | 저속으로 분류된 충돌 횟수 |
| 고속 충돌 | 고속으로 분류된 충돌 횟수 |
| 당일 실적 | 환자 상태, 무사고 보너스, 충돌 감점을 반영한 결과 |
| 누적 실적 | 1일차부터 이번 날까지의 확정 실적 합계이며 정기 평가에 사용하는 값 |

결과 텍스트의 정보 구성 예시는 다음과 같다. 중괄호는 실제 기록이나 추후 확정할 값으로 대체하는 자리이며, UI 디자인이나 최종 문구를 확정한 것은 아니다.

```text
{일차}일차 후송 결과
환자 잔여 HP: {잔여 HP}%
환자 상태: {안정 / 위험 / 위독 / 사망}
차량 충돌: {없음 / 있음}
저속 충돌: {횟수}회
고속 충돌: {횟수}회
당일 실적: {당일 실적}
누적 실적: {누적 실적}
```

병원 인계 시점의 기록으로 결과 수치를 확정하고, 결과 확인으로 하루를 완료할 때 실적을 반영한다. 결과 화면에는 이번 날을 포함한 합산 값을 표시한다. 결과 표시 후 대기 시간이나 확인 입력의 반복으로 기록 및 실적이 바뀌거나 중복 합산되지 않아야 한다.

### 결과·평가 화면의 확인 방식

화면은 자동으로 닫지 않고 다음 버튼 입력으로 진행한다. 아래 버튼 이름과 이동 흐름은 확정이며, 상세 배치·디자인과 안내 문구는 추후 정한다.

| 화면 | 버튼 | 처리 및 다음 화면 |
| --- | --- | --- |
| GamePlay 후송 결과 | `확인` | 당일 실적과 다음 일차를 함께 저장하고 다음 일차 Waiting으로 복귀 |
| Waiting 정기 평가 통과 | `계속하기` | 평가 완료와 다음 누적 목표를 함께 저장하고, 기존 누적 실적을 유지한 채 새 목표 안내 및 미션 요청 대기로 진행 |
| Waiting 정기 평가 미달·해고 | `다시 시작` | 진행 기록을 초기화·저장하고 첫 구간 목표의 1일차 Waiting으로 진입 |

6·11·16일차 등 평가가 필요한 날은 후송 결과의 `확인` 이후 Waiting에 복귀해 평가를 먼저 표시한다. 평가 통과 화면에서 `계속하기`를 누르기 전에는 새 미션 요청을 시작하지 않는다.

## 5. 환자 상태와 사망 처리

- 결과에는 잔여 HP 수치와 환자 상태를 함께 표시한다.
- 상태는 병원 인계 시 실제 남은 HP로 판정한다. 아래 경계값은 확정이며, 상태 이름 자체는 추가 점수나 감점을 발생시키지 않는다.

| 환자 상태 | 병원 인계 시 남은 HP |
| --- | --- |
| 안정 | 70% 이상 |
| 위험 | 30% 이상, 70% 미만 |
| 위독 | 0% 초과, 30% 미만 |
| 사망 | 0% |

- 후송 중 HP가 0이 되어도 즉시 결과 화면으로 전환하거나 해고하지 않는다.
- HP가 0인 경우에도 병원까지 운행을 계속한다.
- 병원 도착 후 사망 결과를 표시하고 당일 실적은 0으로 처리한다. 무사고였어도 사망 시 보너스를 지급하지 않는다.
- 사망한 날도 하나의 미션을 수행한 하루로 계산한다. 결과 확인 후 일반 일차는 다음 날로 진행하고, 5의 배수 일차는 다음 날로 넘어갈 때 정기 평가를 거친다.
- 사망 시 실적 0은 확정 규칙이다. 생존 시 환자 점수·무사고 보너스·충돌 감점은 7절의 확정 배점을 따른다.

기존 환자 HP 감소 방식의 변경은 이번 기획에 포함하지 않는다.

### HP 표시와 판정에 사용할 값

- 계산과 판정에는 표시용으로 가공하지 않은 실제 HP를 사용한다. 표시값으로 환자 HP 원본을 덮어쓰지 않는다.
- 일반 HP 표시는 백분율의 소수점 첫째 자리까지 내림한다. 예를 들어 실제 HP 69.99%는 `69.9%`로 표시한다.
- 실제 HP가 0% 초과~0.1% 미만이면 `0.1% 미만`으로 표시한다. 살아 있는 환자를 `0.0%`로 표시하지 않는다.
- 실제 HP가 0%이면 `0.0% · 사망`으로 표시한다.
- 환자 상태는 실제 HP로 판정한다. 예를 들어 69.99%는 위험, 29.99%는 위독이며 표시를 위해 상태 판정값을 반올림하지 않는다.

## 6. 차량 충돌 기록

### 기록 범위

- 출동하여 GamePlay에서 주행을 시작한 시점부터 병원 인계까지 기록한다.
- 환자 픽업 장소로 가는 도중의 충돌도 포함한다.
- 평가 대상은 플레이어 구급차와 다른 차량 사이의 충돌이다.
- 다른 차량끼리 발생한 충돌이나 건물·벽 등 차량 이외 대상과의 접촉은 이 평가 항목에 포함하지 않는다.
- 병원 인계 후 결과를 보는 동안에는 기록을 추가하지 않는다.

### 횟수 계산

- 같은 차량과 계속 접촉하는 동안은 1회로 계산한다.
- 같은 차량과 떨어진 뒤 다시 충돌하면 추가 1회로 계산한다.
- 서로 다른 차량과의 충돌은 각각 기록한다.
- 하나의 충돌을 저속과 고속에 중복 기록하지 않는다.
- 저속·고속 충돌 합계가 0회면 무사고, 1회 이상이면 사고 있음으로 표시한다.

### 저속·고속 구분

- 구급차의 단독 주행 속도나 상대 속도 전체 크기 대신 부딪힌 방향의 상대 속도를 충격 속도로 사용한다.
- 첫 접촉 순간의 접촉점마다 상대 속도를 접촉 법선 방향으로 투영한 절댓값을 구하고, 그중 가장 큰 값을 사용한다. 기존 환자 충돌 피해 계산과 같은 산정 방식이다.
- 프로젝트의 1유닛=6m 스케일을 따라 월드 유닛/초 값에 6 × 3.6을 곱해 km/h로 환산한다.
- 저속·고속 분류는 각 충돌의 첫 접촉 순간의 충격 속도로 결정한다. 같은 차량과 접촉을 유지하는 동안 속도가 달라져도 해당 충돌을 재분류하거나 추가 집계하지 않는다.
- 분리 후 같은 차량과 다시 충돌하면 새로운 첫 접촉 순간의 속도로 분류한다.
- 충격 속도 40km/h 미만은 저속, 40km/h 이상은 고속이다. 정확히 40km/h인 경우 고속으로 분류한다.
- 충돌 분류에는 표시용 반올림·내림을 적용하지 않은 실제 충격 속도를 사용한다. 예를 들어 39.99km/h는 저속이며, 반올림해 고속으로 처리하지 않는다.
- 이번 평가는 기존 차량 파손 판정이나 환자 충돌 피해 계산과 별개다. 평가 기준을 추가한다는 이유로 기존 물리 동작을 변경하지 않는다.

## 7. 실적 계산과 누적 집계

```text
생존 시 계산값 = max(0, 환자 점수 + 무사고 보너스 - 충돌 감점)
생존 시 당일 실적 = 계산값을 마지막에 한 번 정수로 반올림
환자 점수 = 100점 × 병원 인계 시 남은 HP 비율 = 남은 HP 1%당 1점
무사고 보너스 = 생존하고 기록 대상 차량 충돌이 0회이면 30점, 그 외에는 0점
충돌 감점 = 저속 충돌 횟수 × 2점 + 고속 충돌 횟수 × 10점
사망 시 당일 실적 = 0
누적 실적 = 1일차부터 현재 일차까지 완료한 날의 확정 정수 실적 합계
부족 실적 = max(0, 다음 평가의 누적 목표 - 누적 실적)
```

- 하루 동안 기록한 항목을 후송 결과에서 실적으로 환산한다.
- HP 비율은 0~1로 사용한다. 안정·위험·위독은 결과 설명용으로 표시하고, 점수는 상태별 고정값 대신 병원 인계 시 남은 HP에 비례해 계산한다.
- 환자 점수를 주된 비중으로 두고, 무사고 보너스는 보조 비중으로 둔다. 생존 여부와 환자 상태가 실적의 중심이 되도록 배점을 조정한다.
- 생존 시 무사고 보너스는 기록 대상 차량 충돌이 한 번도 없을 때 적용한다.
- 충돌이 있으면 무사고 보너스 없이 저속·고속 충돌 횟수에 따른 감점을 적용한다.
- 저속 충돌은 1회당 2점, 고속 충돌은 1회당 10점을 감점한다. 고속 충돌 1회 감점은 저속의 5배다.
- 사망 시에는 무사고 보너스를 지급하지 않고 당일 실적을 0으로 처리한다.
- 당일 실적의 하한은 0이다. 충돌 감점으로 이미 완료한 이전 날의 실적을 줄이지 않는다.
- 시간에 따른 HP 감소와 충돌에 따른 HP 감소는 기존 방식으로 반영한다. 별도 시간 감점은 추가하지 않는다.
- 픽업 완료 등 진행 단계마다 별도 점수를 즉시 지급하는 방식은 현재 확정 범위에 포함하지 않는다.
- 결과 하나는 누적 실적에 한 번만 반영한다.
- 일차가 바뀌면 당일 환자·충돌 기록은 새로 시작하지만, 누적 실적은 이번 플레이 동안 유지한다.
- 정기 평가에는 1일차부터 현재 평가일까지의 누적 실적을 사용한다. 예를 들어 6일차 진입 시 1~5일, 11일차 진입 시 1~10일의 합계를 평가한다.
- 평가 통과 시 누적 실적을 초기화하거나 목표만큼 차감하지 않는다. 목표 초과분도 누적 실적에 남아 다음 평가에 사용된다.
- 각 구간 기준 요구량은 누적 목표를 계산하기 위한 값이다. 해당 5일 동안 그 기준 요구량을 별도로 달성해야 하는 조건은 두지 않는다.
- 위 계산 방식과 환자 점수 100점 배점·무사고 보너스 30점·저속 2점 및 고속 10점 감점은 확정 규칙이다. 아래 소수점·반올림 규칙을 함께 적용한다.
- 이론상 일일 최대 실적은 130점, 5일 구간 최대 실적은 650점이다. 실제 후송에서는 시간 경과에 따른 HP 감소 등이 있으므로 달성 가능한 실적을 측정한 값이 아니다. 별도 추가 점수 상한은 도입하지 않으며, 이론상 최대값을 구간 목표로 자동 지정하지 않는다.

### 실적의 소수점·반올림 기준

- 환자 점수는 병원 인계 시 실제 HP로 계산한다. 내림한 표시용 HP를 점수 계산에 사용하지 않는다.
- 환자 점수·무사고 보너스·충돌 감점을 중간 단계에서 각각 반올림하지 않는다.
- 모든 항목을 합산하고 하한 0을 적용한 계산값을 마지막에 한 번 정수로 반올림한다. 소수 부분이 0.5 이상이면 올림, 0.5 미만이면 내림한다. 예를 들어 102.5점은 103점이다.
- 사망 시에는 위 생존 계산과 무사고 보너스를 적용하지 않고 당일 실적을 정수 0점으로 확정한다.
- 결과 화면에 표시하고 하루 완료 시 저장하는 당일 실적은 동일한 확정 정수 값이다. 결과 대기나 재시도로 다시 계산하여 값이 바뀌지 않아야 한다.
- 누적 실적은 완료한 날의 확정 정수 실적만 합산해 표시·저장한다. 5일 평가 때 원본 소수 실적을 다시 합산하거나 재반올림하지 않는다.
- 누적 목표와 부족 실적도 정수로 표시한다. 확정된 누적 정수 실적이 해당 평가의 정수 누적 목표 이상이면 통과하며, 화면에 표시한 값과 실제 합격 판정값을 일치시킨다.

## 8. 정기 평가와 재시작

| 조건 또는 입력 | 결과 |
| --- | --- |
| 매 5일 결과 확인 후 다음 일차 Waiting 진입 시, 누적 실적이 해당 누적 목표 이상 | 평가 통과 화면에서 `계속하기` 입력 후 누적 실적을 유지하고 다음 누적 목표로 해당 일차 요청 대기 |
| 매 5일 결과 확인 후 다음 일차 Waiting 진입 시, 누적 실적이 해당 누적 목표 미만 | 해고 상태를 저장하고 해고 화면 표시 |
| 해고 화면에서 `다시 시작` 선택 | 진행 정보와 목표 진행 상태를 초기화·저장하고 첫 구간 목표의 1일차 Waiting으로 진입 |

- 목표와 정확히 같은 실적도 평가 통과로 처리한다.
- 평가는 5·10·15일차 등 각 5일 구간의 마지막 날을 마치고 다음 날로 넘어갈 때 수행한다. 목표에 일찍 도달해도 다음 정기 평가 시점까지 하루에 한 미션씩 진행한다.
- 통과 후에는 6·11·16일차 등 다음 일차로 이어지며, 일차 상한이나 최종 클리어 일차는 두지 않는다.
- 각 평가를 통과하면 다음 누적 목표는 아래 확정 공식으로 계산한다. 첫 구간 기준 요구량은 200점, 구간별 기준 요구량 증가분은 20점이며 상한이나 상승 비율은 사용하지 않는다.
- 환자 사망이나 당일 실적 부족만으로 중간에 해고하지 않는다.
- 해고 후 재시작 시 일차, 누적 실적, 평가 목표의 진행 상태, 이전 일차의 결과 및 당일 환자·충돌 기록을 초기화한다. 첫 누적 목표 200점부터 다시 시작한다. 누적 실적을 유지하는 정기 평가 통과와 구분한다.
- 이전 플레이의 출동 승인, 진행 중인 미션이나 생성된 맵을 이어받지 않는다.
- 기존 랜덤 시드 생성 방식을 다시 사용한다. 동일한 시드나 맵을 재현하도록 고정하지 않는다.
- 영구 성장, 장비·재화 계승, 해금 및 재도전 전용 변형 요소는 현재 기획에 추가하지 않는다.

### 목표 증가 공식

k는 1부터 시작하는 5일 평가 구간 번호다.

```text
k번째 구간 기준 요구량 = 200점 + (k - 1) × 20점
k번째 평가의 누적 목표 = 1번째부터 k번째 구간 기준 요구량의 합계
                         = 200k + 10k(k - 1)점
평가 통과 후 다음 누적 목표 = 현재 누적 목표 + 다음 구간 기준 요구량
k번째 구간의 수행 일차 = (5k - 4)일차 ~ 5k일차
평가 시점 = (5k + 1)일차 Waiting 진입 시
```

- 2026-10-28 사용자 지시에 따라 구간 실적 초기화 방식과 독립 구간 목표를 위 누적 방식으로 대체한다. 기존 상한 접근 공식과 목표 상한·상승 비율은 사용하지 않는다.
- 각 구간 기준 요구량은 200·220·240·260점으로 증가하고, 평가에 사용할 누적 목표는 200·420·660·920점으로 증가한다. 평가 전 해당 평가의 목표를 다음 목표로 먼저 올려 비교하지 않는다.
- 목표 상한은 두지 않고, 목표가 달성 가능한 실적을 넘어서면 해고되는 구조를 사용자 승인으로 허용한다.
- 이론상 5일 최대 실적 650점은 새로 얻을 수 있는 실적의 상한이다. 누적 평가에서는 이전 구간의 초과 실적도 사용하므로, 특정 구간의 기준 요구량이 650점을 넘었다는 이유만으로 그 평가를 즉시 통과 불가능으로 단정하지 않는다. 이전 독립 평가 방식의 121일차 한계 계산은 폐기한다.
- 누적 목표는 정수이며, 평가에는 7절에 따라 매일 확정한 정수 실적의 누적 합계를 사용한다.
- 예를 들어 5일차까지 250점을 얻었다면, 10일차 누적 목표 420점까지 추가로 필요한 실적은 170점이다. 6~10일차에 170점을 얻어도 누적 420점으로 통과하며, 해당 구간 기준 요구량 220점을 별도로 요구하지 않는다.

| 수행 구간 | 구간 기준 요구량 | 평가 누적 목표 | 평가 시점 |
| --- | --- | --- | --- |
| 1~5일차 | 200점 | 200점 | 6일차 Waiting |
| 6~10일차 | 220점 | 420점 | 11일차 Waiting |
| 11~15일차 | 240점 | 660점 | 16일차 Waiting |
| 16~20일차 | 260점 | 920점 | 21일차 Waiting |
| 21~25일차 | 280점 | 1,200점 | 26일차 Waiting |

### 게임 종료와 재실행

- 일반적인 재실행은 진행 중이던 일차의 Waiting에서 미션을 수락하기 전 상태로 돌아간다. 정기 평가 대기 또는 해고 상태가 저장되어 있으면 아래 규칙에 따라 해당 화면을 먼저 표시한다.
- 이미 완료한 이전 일차의 실적과 현재 구간의 목표 진행 상태는 유지한다. 일반적인 게임 종료를 해고 후 1일차 초기화와 동일하게 처리하지 않는다.
- 그날 수락한 미션, 차량 위치, 환자 상태, 충돌 횟수 등 미완료 진행은 이어받지 않고 그날을 다시 시작한다.
- 해당 일차 재도전 시 이전 맵이나 시드를 복원하지 않는다. 다시 출동할 때 기존 랜덤 시드 생성 방식으로 맵을 새로 생성한다.
- 결과를 확인하기 전에 종료하면 해당 일차는 미완료로 취급한다. 그날의 임시 결과를 실적에 남긴 채 같은 날을 다시 수행하지 않는다.
- 이 규칙에 따라 사고나 사망 결과를 확인하지 않고 종료한 뒤 새 맵으로 재도전할 수 있다. 현재 기획에서는 이를 허용하며, 별도의 종료 페널티나 재도전 제한은 추가하지 않는다.
- 예를 들어 3일차 후송 도중 종료하면, 재실행 시 1~2일차 확정 실적을 유지한 채 3일차 미션 수락 전으로 돌아간다.
- 완료한 날의 결과를 다시 합산하거나, 재실행으로 필수 정기 평가를 건너뛰어 새 미션을 받지 않아야 한다.

### 백그라운드 일시정지와 복귀

- 다른 앱이나 브라우저 탭으로 이동해 게임이 백그라운드로 전환되면 게임 진행을 일시정지한다.
- 일시정지 동안 플레이어 차량·교통 차량의 주행, 환자 HP 시간 감소, 구출 컷신과 미션 요청 대기 타이머 등 게임 진행을 멈춘다. 백그라운드 경과 시간을 복귀 시 추가 진행으로 반영하지 않는다.
- 실행 세션이 유지된 상태에서 게임으로 돌아오면 같은 일차·맵·미션 단계와 차량·환자·충돌 기록을 유지하고 이어간다.
- 백그라운드 전환 자체를 하루 완료, 실적 확정, 미션 취소나 새 맵 재도전으로 처리하지 않는다.
- 실제 종료, 페이지 재실행 또는 실행 세션 종료 후 새로 시작하는 경우에만 기존 재실행 복귀 규칙을 적용한다. 이 경우에는 해당 일차의 미션 수락 전으로 돌아가고 다시 출동할 때 새 맵을 생성하되, 평가 대기·해고 상태는 우선 복원한다.

### 저장 시점과 재실행 상태

- 후송 결과의 `확인`을 누를 때 당일 실적 반영과 다음 일차 진행을 하나의 완료 처리로 함께 저장한다. 종료 시점에만 저장하는 방식으로 미루지 않는다.
- `확인` 전 종료하면 그날을 다시 시작한다. `확인` 후 종료하면 다음 날의 미션 수락 전 상태로 복귀한다. 다음 날이 정기 평가일이면 평가를 먼저 표시한다.
- 5·10·15일차 결과 확인 시에는 다음 일차와 함께 정기 평가 대기 상태를 저장한다. 이번 날을 반영한 누적 실적과 해당 평가의 누적 목표를 유지한다.
- 평가 도중 종료해도 평가 대기 상태를 유지한다. 재실행 시 새 미션 요청보다 평가 화면을 먼저 표시한다.
- 평가 통과 화면에서 `계속하기`를 누를 때 평가 완료와 다음 누적 목표를 하나의 처리로 함께 저장한다. 기존 누적 실적은 그대로 유지하며, 재실행이나 중복 입력으로 목표를 두 번 올리거나 실적을 차감하지 않는다.
- 평가 미달로 해고되면 해고 상태를 저장한다. `다시 시작`을 누르지 않고 종료하면 재실행해도 해고 화면을 유지한다.
- 해고 화면의 `다시 시작`을 누를 때 이전 플레이 기록을 초기화하고, 첫 구간 목표의 1일차 상태를 저장한 뒤 Waiting으로 진행한다.
- 위 항목은 저장할 게임 상태와 시점에 대한 확정 규칙이다. 저장 API·파일 형식 등 기술 구현 방식은 이 문서에서 지정하지 않는다.

### 저장 범위와 실패 처리

- 저장 범위는 현재 기기의 로컬 저장으로 한정한다. 계정 연동이나 다른 기기와의 저장 동기화는 추가하지 않는다.
- 저장 성공을 확인한 뒤에만 해당 입력에 따른 다음 단계로 진행한다. 저장 실패를 성공으로 취급하지 않는다.
- 저장에 실패하면 현재 화면에 실패 사실과 재시도 수단을 제공하고, 다음 일차·새 구간·재시작 화면으로의 진행을 보류한다.
- 같은 저장을 재시도해도 실적 합산, 날짜 증가, 목표 상승이나 초기화가 중복 적용되지 않아야 한다.
- 저장 실패를 이유로 기존 정상 저장을 임의로 삭제하거나 1일차로 초기화하지 않는다.

### 저장 데이터 읽기 실패

- 저장 데이터가 없음을 정상적으로 확인한 경우와, 기존 저장 데이터를 읽거나 해석하지 못한 경우를 구분한다.
- 정상 확인 결과 저장이 없으면 기존 규칙대로 첫 구간 목표의 1일차로 시작한다.
- 읽기 실패나 손상으로 진행 상태를 확인할 수 없으면 오류와 읽기 재시도를 표시한다. 이를 저장 없음으로 간주해 1일차로 자동 초기화하지 않는다.
- 읽기에 실패한 기존 데이터를 삭제하거나 새 게임 데이터로 자동 덮어쓰지 않는다. 정상적인 저장 상태를 확인하기 전에는 미션 진행과 새 진행 데이터 저장을 시작하지 않는다.
- 재시도에 성공하면 읽은 상태에 따라 일반 진행·평가 대기·해고 화면으로 진입한다. 다시 실패하면 오류와 재시도 상태를 유지한다.

## 10. 구현 시 확인할 완료 조건

아래는 향후 구현 검증 기준이다. 이번 문서 작성에서 실행하거나 통과한 테스트 목록이 아니다.

- [ ] 새 플레이가 1일차 Waiting에서 시작한다.
- [ ] Start의 `시작하기`가 저장 없음·일반 진행·평가 대기·해고에 따라 올바른 Waiting 상태로 진입한다.
- [ ] 저장이 실제로 없는 경우에만 새 1일차를 시작하며, 읽기 실패·손상 시에는 기존 데이터를 유지하고 오류와 재시도를 표시한다.
- [ ] 읽기 재시도 성공 시 저장된 일반 진행·평가 대기·해고 상태로 복귀하고, 실패가 계속되면 새 진행으로 덮어쓰지 않는다.
- [ ] 기존 요청 확인·수락·출동 및 랜덤 시드 생성 흐름이 유지된다.
- [ ] 미션 수락·거절·출동·환자 픽업만으로 일차가 증가하지 않는다.
- [ ] 5의 배수가 아닌 일차는 병원 인계 결과 확인 후 다음 일차 Waiting으로 진행한다.
- [ ] 병원 인계 시 잔여 HP, 환자 상태, 사고 여부와 저속·고속 충돌 횟수가 정확히 표시된다.
- [ ] 픽업 전 충돌이 기록되고, 같은 차량과 지속 접촉은 중복 집계되지 않으며, 분리 후 재충돌은 추가 집계된다.
- [ ] 충격 속도에 따라 충돌 하나가 저속 또는 고속 중 하나에만 기록된다.
- [ ] 저속·고속은 첫 접촉 순간의 속도로 결정하며, 지속 접촉 중 속도 변화는 재분류하지 않고 분리 후 재충돌은 새로 분류한다.
- [ ] 접촉 법선 방향 상대 속도 절댓값의 최댓값으로 판정하고, 정확히 40km/h인 충돌은 고속으로 분류한다.
- [ ] HP 0 이후에도 운행할 수 있고, 병원 도착 후 사망 결과가 표시된다.
- [ ] 무사고·사고·사망 결과에 확정된 실적 규칙이 적용된다.
- [ ] 환자 점수가 잔여 HP에 비례하며 안정·위험·위독 표시 경계에서 별도 점수 변화가 발생하지 않는다.
- [ ] 생존·무사고인 경우에만 무사고 보너스가 적용되고, 사망한 날의 실적은 0이다.
- [ ] 고속 충돌 1회 감점이 저속 충돌 1회보다 크며, 당일 실적은 0 미만이 되지 않는다.
- [ ] 잔여 HP 1%당 1점·생존 무사고 보너스 30점·저속 1회 2점·고속 1회 10점 감점으로 계산된다.
- [ ] HP가 정확히 70%이면 안정, 정확히 30%이면 위험, 0%이면 사망으로 표시된다.
- [ ] 실제 HP 69.99%는 위험·표시 69.9%이고, 실제 충격 속도 39.99km/h는 저속으로 판정된다.
- [ ] HP가 0% 초과~0.1% 미만이면 `0.1% 미만`, 실제 0%이면 `0.0% · 사망`으로 구분된다.
- [ ] 실제 HP로 중간 반올림 없이 실적을 계산하고, 최종 102.46점은 102점·102.50점은 103점으로 확정한다.
- [ ] 누적 실적은 당일 확정 정수 값만 합산하며, 표시·저장·평가에 같은 값을 사용한다.
- [ ] 시간 경과에 따른 HP 감소 외에 별도 시간 감점을 적용하지 않는다.
- [ ] 결과 확인을 반복해도 실적이 중복 반영되거나 일차가 두 번 증가하지 않는다.

## 11. 작성 시 확인한 구현과의 차이

2026-10-28 소스 확인 기준이다. Unity Editor에서 기능을 실행 검증한 결과가 아니다.

- `MissionController.CompleteMission()`은 병원 도착 후 결과 확인 단계 없이 Waiting으로 전환한다. 기획 적용 시 결과 확인과 일차별 분기가 필요하다.
- `PatientHealth`는 HP를 관리하지만 HP 0에서 미션 종료를 요청하지 않는다. 승인된 사망 처리도 즉시 종료 없이 병원 후송을 유지한다.
- `MissionDispatchSession`은 다음 출동 승인 전달을 담당한다. 일차·누적 실적과 하루 결과의 유지·초기화는 별도로 구현해야 한다.
- `PerformanceRules`와 `GameProgress`에 순수 계산 및 진행 상태를 구현했다. 아직 기존 미션·씬에서 호출하지 않으며, 저장·화면 연결은 다음 단계의 범위다.
- 기존 `Md/MISSION_DISPATCH.md`의 반복 출동 검증은 기존 흐름에 대한 기록이다. 새 날짜·실적·정기 평가 기능을 검증한 것으로 간주하지 않는다.

최초 기획 작성에서는 문서화만 수행했다. 이후 준비 단계·1단계의 구현·컴파일·테스트와 미검증 범위는 [준비·1단계 결과](DAY_PERFORMANCE_STAGE1.md)에 기록한다.
