# CodeBlueRush 개발 작업 지시

> 현재 구조 (2026-10-03): 맵은 Scene에 저장된 고정 World를 사용한다. 아래 개발 단계의 Seed 생성·도시 생성·실패 후 WorldReset 설명은 과거 기록이며 현재 동작에 적용하지 않는다.

Git Commit / Push는 절대 하지 않는다.

→ 도시 생성  
→ 상황 보고 발생  
→ 환자 위치 랜덤 결정

→ 새로운 도시 생성  
→ 새로운 상황 보고부터 시작

# 핵심 게임 규칙

## 환자 체력 / 심전도

게임에서 체력 개념은 **오직 환자의 심전도 상태**만 사용한다.

다음 체력 시스템은 만들지 않는다.

- 구급차 내구도
- 플레이어 HP

환자 심전도 최대값은 100이다.

상태 판정:

- ECG >= 60: 초록
- ECG >= 10: 노랑
- ECG > 0: 빨강
- ECG <= 0: Flatline

숫자 제한시간 UI는 표시하지 않는다.

환자 픽업 완료 후 심전도가 감소하기 시작한다.

기본 생존 시간은 **180초**이며 이후 플레이테스트에서 조정할 수 있도록 `public float survivalTime = 180f` 형태로 수정 가능하게 한다.

기본 감소는 최대 ECG 100이 `survivalTime` 동안 0까지 감소하도록 계산한다.

심전도 상태는 다음 연출로 표현한다.

- 색상
- 파동 크기
- 파동 강도

ECG UI가 별도의 타이머나 별도 체력값을 가지면 안 된다.

실제 환자 ECG 값 하나를 기준으로 모든 UI 연출을 계산한다.

ECG가 0이 되면 Flatline 상태로 전환하고 `PatientDied` 이벤트를 발생시킨다.

심전도 시스템 자체가 Game Over, 맵 제거, Seed 생성, 새 미션 시작을 직접 처리하지 않는다.

Game Over 흐름은 최종 GameFlow가 담당한다.

---

# 충돌 규칙

환자 픽업 전:

- 심전도 피해 없음
- 물리 충돌은 발생
- 넉백 발생
- 약 2초 경직 발생
- 경직 후 구급차 조작 복구

환자 픽업 후:

- 구급차 속도 < 4: 저속 충돌 → 심전도 -50
- 구급차 속도 >= 4: 고속 충돌 → 치명 충돌 처리

구급차 최고속도 기준값은 10이다.

고속 충돌은 치명 충돌 이벤트를 발생시키고 최종 GameFlow에서 Game Over로 전환한다.

충돌 물리:

- 충돌 지점 확인
- 각 차량 이동 방향 확인
- 충돌 지점에서 서로 반대 방향으로 넉백
- 구급차 조작 잠금
- 약 2초 경직
- 조작 복구

동일한 충돌 접촉으로 피해가 여러 번 적용되지 않도록 한다.

---

# 결과 평가

결과 평가는 병원 도착 후 **14단계에서 최종 처리**한다.

- 충돌 0회 + 초록 → ★★★
- 충돌 0회 + 노랑 → ★★★
- 충돌 0회 + 빨강 → ★★
- 충돌 1회 + 노랑 → ★★
- 충돌 1회 + 빨강 → ★
- 충돌 1회 + 초록 → 발생 불가능
- 충돌 2회 → 심전도 0 → Game Over
- 고속 충돌 → 즉시 Game Over

병원에 정상 도착한 순간 심전도 감소를 먼저 중지하고 현재 상태를 확정한 뒤 결과를 계산한다.

---

# 도시 / 병원 규칙

도시는 게임 시작 시 Seed를 기준으로 한 번 생성한다.

성공한 미션에서는 같은 도시를 유지한다.

새로운 상황 보고가 발생하면 도시를 다시 생성하지 않고 환자 위치만 새로 선택한다.

Game Over 후에만:

기존 도시 제거  
→ 새로운 Seed  
→ 새로운 도시 생성

순서로 진행한다.

랜덤 도시에는 **최소 1개의 유효한 병원**이 존재해야 한다.

병원은:

- 차량이 실제 도로를 통해 접근 가능해야 함
- Navigation 경로가 존재해야 함
- `HospitalPoint` 또는 이에 준하는 위치 데이터를 가짐
- 병원 도착 판정을 위한 `HospitalArrivalZone`을 가짐

3단계 랜덤 맵 시스템에 병원 위치 데이터가 아직 없다면 기존 맵 생성 구조를 재작성하지 말고 8단계에서 최소 확장한다.

---

# 미션 Reset 규칙

## 미션 성공

병원 도착  
→ ECG 감소 중지  
→ 결과 평가  
→ 결과 UI  
→ 현재 도시 유지  
→ 현재 미션 상태만 Reset  
→ 새로운 상황 보고

새 미션 시작 전 최소 다음 상태를 초기화한다.

- 이전 MissionId 종료
- 새 MissionId 생성
- 환자 탑승 상태
- 심전도 상태
- 충돌 횟수
- 이전 환자 / 구급대원 상태
- 이전 Navigation 경로 / 목적지
- 이전 병원 목적지
- 이전 미션 이벤트 상태

## Game Over

PatientDied 또는 치명 충돌  
→ GameOver 상태 전환  
→ 현재 미션 종료  
→ 기존 도시 제거  
→ 이전 미션 참조 정리  
→ 새로운 Seed 생성  
→ 새로운 도시 생성  
→ 새로운 상황 보고

성공 Reset과 Game Over Reset을 같은 방식으로 처리하지 않는다.

# 개발 순서

각 단계는 이전 단계가 정상 동작하는 것을 확인한 뒤 진행한다.

현재 요청받은 **한 단계만 구현**하고 다음 단계 기능을 미리 구현하지 않는다.

---

## 2단계 — 도로 / 차선 시스템

랜덤 맵, 차량 AI, 네비게이션이 공통으로 사용할 도로 기반 시스템을 만든다.

도로 Prefab 자체가 차선 데이터를 가진다.

필요 기능:

- 직선 도로
- 코너 도로
- 2차선 이상 지원
- TrafficLane
- Lane 진행 방향
- Next Lane
- Left Lane
- Right Lane
- 도로 연결 지점
- Lane 연결 지점

차량이 Sprite 위치를 추측해서 움직이는 구조는 사용하지 않는다.

차량은 TrafficLane 데이터를 따라 이동한다.

Lane의 Left / Right / Next 관계는 가능하면 직접 참조하여 반복 검색을 피한다.

---

## 3단계 — 랜덤 맵 생성

RoadChunk 단위의 규칙 기반 랜덤 도시를 생성한다.

지원 구조 예:

- Straight
- Corner
- T-Junction
- 4-Way Intersection

생성 흐름:

Seed  
→ 도로 구조  
→ 차선 연결  
→ 교차로 구조  
→ 횡단보도 위치  
→ 보도  
→ 건물  
→ 장식

완전 무작위 배치가 아니라 연결 가능한 규칙형 생성으로 구현한다.

도로가 끊기거나 이동 불가능한 맵이 생성되면 안 된다.

교차로는 이 단계에서 **도로 구조와 Lane 연결 기반**을 생성한다.

신호등, 차량 정지 제어, 보행자 신호 같은 실제 교통 제어 기능은 11단계에서 기존 교차로 구조를 확장한다.

맵은 상황 보고마다 다시 생성하지 않는다.

게임 시작 시 한 번 생성하고 성공한 미션에서는 같은 도시를 유지한다.

Game Over 후에만 새로운 Seed로 새로운 도시를 생성한다.

랜덤 도시 구조는 향후 유효한 병원 위치를 등록할 수 있어야 한다.

---

## 4단계 — 네비게이션

랜덤 생성된 실제 도로 연결 데이터를 사용해 경로를 계산한다.

상황 보고 발생  
→ 환자 위치 결정  
→ 현재 구급차 위치에서 환자 위치까지 경로 계산  
→ 네비게이션 UI 표시

환자 픽업 후에는 8단계 병원 시스템이 병원 위치를 목적지로 전달한다.

도로와 별개의 가짜 네비게이션 도로를 만들지 않는다.

랜덤 맵에서 생성된 실제 RoadChunk / TrafficLane 연결 정보를 사용한다.

목적지가 변경되었을 때 필요한 경우에만 경로를 다시 계산하고 매 프레임 전체 경로를 재탐색하지 않는다.

---

## 5단계 — 상황 보고 / 환자 위치

같은 도시 안에서 유효한 환자 위치를 랜덤 선택하는 미션 시스템을 만든다.

상황 보고 시:

- MissionId 생성
- 유효한 환자 위치 결정
- 상황 보고 UI 표시
- 네비게이션 목적지 설정

환자 위치는 차량이 도로를 통해 접근할 수 있어야 한다.

이전 상황 보고의 환자 위치, Navigation 목적지, 미션 참조가 새 미션에 남지 않도록 한다.

---

## 6단계 — 환자 픽업

사고 현장에는:

- 환자
- 구급대원
- 픽업 판정 영역

이 존재한다.

구급차가 지정된 위치에 도착해 정상적으로 정차하면 픽업을 시작한다.

환자와 구급대원이 구급차 뒤쪽 `RearBoardingPoint`로 이동한다.

픽업 중 구급차가 다시 움직이면 이동을 일시정지하고 다시 정차하면 이어서 이동한다.

탑승 위치에 도착하면 환자와 구급대원을 숨기거나 비활성화한다.

이후:

- `IsPatientOnBoard = true`
- `PatientPickedUp` 이벤트 1회 발생
- 중복 픽업 방지

6단계에서는 병원 선택이나 병원 Navigation 전환을 직접 구현하지 않는다.

`PatientPickedUp` 이벤트를 7단계 심전도와 8단계 병원 시스템의 연결 지점으로 사용한다.

---

## 7단계 — 심전도 시스템

`PatientPickedUp` 이벤트를 기준으로 심전도 감소를 시작한다.

심전도 최대값은 100이다.

기본 생존 시간:

`public float survivalTime = 180f`

플레이테스트에서 수정할 수 있어야 한다.

상태:

- ECG >= 60 → Green
- ECG >= 10 → Yellow
- ECG > 0 → Red
- ECG <= 0 → Flatline

UI에는 숫자 카운트다운을 표시하지 않는다.

ECG 실제 값을 기준으로 다음을 변화시킨다.

- 색상
- 파동 크기
- 파동 강도

심전도 감소가 중복 실행되지 않도록 한다.

환자를 아직 픽업하지 않았다면 심전도가 감소하면 안 된다.

병원 도착 시 심전도 감소를 즉시 중지할 수 있는 API를 제공한다.

ECG가 0이 되면:

- 0 이하로 Clamp
- Flatline 연출
- 감소 중지
- `PatientDied` 이벤트 1회 발생

심전도 시스템은 Game Over 흐름을 직접 실행하지 않는다.

---

## 8단계 — 병원 시스템

랜덤 도시의 유효한 병원 위치를 사용한다.

도시에는 최소 1개의 접근 가능한 병원이 존재해야 한다.

병원에 필요한 최소 데이터:

- HospitalPoint
- 도로 / Navigation 연결 정보
- HospitalArrivalZone

`PatientPickedUp` 이후:

환자 픽업 완료  
→ 유효한 병원 결정  
→ Navigation 목적지 변경  
→ 현재 위치에서 병원까지 경로 계산  
→ 병원 이송

병원 도착 조건:

- 환자가 탑승한 상태
- 올바른 병원 ArrivalZone 진입

정상 도착하면:

- 심전도 감소 즉시 중지
- 현재 ECG 상태 고정
- 병원 도착 상태 발생

8단계에서는 아직 충돌 횟수 기반 별 평가를 구현하지 않는다.

결과 평가는 13단계 충돌 시스템이 완료된 뒤 14단계에서 처리한다.

현재 랜덤 맵이 병원 위치 데이터를 제공하지 않는다면 3단계 구조를 다시 만들지 말고 필요한 데이터만 최소 확장한다.

---

## 9단계 — 일반 차량 AI

TrafficLane을 따라 움직이는 일반 차량 AI를 구현한다.

필요 기능:

- Lane 따라 이동
- 앞 차량 감지
- 차량 간격 유지
- Next Lane 이동
- 잘못된 Lane 또는 맵 밖 이동 방지

차량은 플레이어 주변 활성 범위의 유효한 TrafficLane에서 생성한다.

Spawn 규칙:

- 플레이어와 너무 가까운 위치에서는 생성하지 않음
- 화면 바로 앞에서 갑자기 보이도록 생성하지 않음
- 유효한 진행 방향 Lane에서만 생성
- 최대 활성 차량 수를 제한
- 플레이어와 충분히 멀어진 차량은 제거하거나 Pool로 반환

매 프레임 전체 Lane 또는 모든 차량을 검색하지 않는다.

차량 재사용이 반복되는 구조라면 Object Pool 사용을 우선 검토한다.

---

## 10단계 — 차선 변경 / 끼어들기

차량 AI가 인접 Lane으로 자연스럽게 이동할 수 있도록 한다.

예:

현재 Lane  
→ Left / Right Lane 확인  
→ 이동 가능한 공간 확인  
→ 차선 변경 결정  
→ 전진하면서 옆 차선으로 이동  
→ Current Lane 변경

순간이동 방식은 사용하지 않는다.

구급차 앞쪽으로 끼어드는 행동을 지원한다.

차선 변경 판단 시 최소 다음을 확인한다.

- 구급차 거리
- 상대 차량 속도
- 현재 Lane
- 인접 Lane
- 주변 차량
- 변경 후 충돌 가능성

무조건적인 랜덤 차선 변경을 사용하지 않는다.

---

## 11단계 — 교차로 / 신호등

3단계에서 생성된 기존 교차로 RoadChunk / Intersection 구조를 재사용한다.

새로운 교차로 시스템을 중복 생성하지 않는다.

기존 교차로 Prefab 또는 구조에 다음 기능을 확장한다.

- TrafficLight
- VehicleStopZone
- Crosswalk
- PedestrianWaitPoint
- TrafficSignalController

교차로 자체가 필요한 신호 / 정지 / 횡단 데이터를 가진다.

랜덤 맵 생성기는 교차로 내부 신호 로직을 직접 제어하지 않는다.

차량 AI:

- 초록 → 진행
- 빨강 → 정차

일부 AI 차량은 별도 행동 조건 또는 제한된 확률로 신호 위반이 가능하다.

신호 위반 차량도 다른 차량과의 즉시 충돌이 확정된 상황에서는 무조건 진입하도록 만들지 않는다.

---

## 12단계 — 시민 AI / 사이렌 시스템

### 시민 경로

시민은 이미지 위치를 추측해서 이동하지 않는다.

`SidewalkPath` 또는 이에 준하는 명확한 보행 경로 데이터를 사용한다.

기본 연결:

SidewalkPath  
→ Crosswalk  
→ SidewalkPath

보행 경로는 최소 다음 정보를 제공할 수 있어야 한다.

- 이동 Point
- Next Path
- 연결된 Crosswalk
- 횡단 후 이어질 SidewalkPath

횡단보도에서는:

- 보행자 빨간불 → 대기
- 보행자 초록불 → 횡단

일부 시민은 별도 행동 조건에 따라 무단횡단할 수 있다.

모든 시민에게 단순 랜덤으로 무단횡단을 실행하지 않는다.

### 사이렌

모바일 클릭 입력을 사이렌 입력으로 사용한다.

기본 동작은 클릭할 때 사이렌 ON / OFF 상태를 전환하는 방식으로 구현한다.

사이렌 상태는 단순 소리 연출뿐 아니라 주변 AI에 영향을 준다.

사이렌 ON 상태에서:

- 앞 차량이 구급차를 인식
- 이동 가능한 경우 안전하게 공간을 확보하거나 양보
- 주변 AI 차량이 구급차 접근에 반응
- 시민이 도로 진입 또는 무단횡단 행동을 억제하거나 멈출 수 있음
- 횡단 중인 시민은 즉시 순간이동하지 않고 안전한 방식으로 행동을 계속하거나 멈춤

사이렌이 신호등 자체를 강제로 초록으로 변경하지는 않는다.

AI 반응은 사이렌이 켜졌다는 이유만으로 충돌 위험이 높은 즉시 차선 변경을 수행하지 않는다.

차량과 시민은 매 프레임 전체 Scene에서 구급차를 검색하지 않고 기존 참조 또는 제한된 감지 범위를 사용한다.

---

## 13단계 — 충돌 / 넉백 / 경직

기존 구급차 이동 시스템, 일반 차량 AI, 환자 심전도와 연결한다.

충돌 시 환자 탑승 여부와 현재 구급차 속도를 확인한다.

### 환자 픽업 전

- 심전도 피해 없음
- 물리 충돌 발생
- 넉백 발생
- 구급차 약 2초 경직
- 경직 종료 후 조작 복구

### 환자 픽업 후

속도 < 4:

- 심전도 -50
- 충돌 횟수 +1
- 넉백
- 약 2초 경직

속도 >= 4:

- 치명 충돌 이벤트
- 넉백 / 필요한 충돌 연출
- GameFlow에서 Game Over 처리

충돌 물리:

- 충돌 지점
- 구급차 진행 방향
- 상대 차량 진행 방향

을 기준으로 서로 반대 방향으로 넉백한다.

동일 접촉으로 심전도 피해 또는 충돌 횟수가 중복 적용되지 않도록 한다.

충돌 시스템은 Game Over 전체 흐름을 직접 관리하지 않는다.

치명 충돌 상태 또는 이벤트만 전달한다.

---

## 14단계 — 결과 평가 / 전체 게임 루프

마지막으로 완성된 시스템들을 GameFlow에 연결한다.

GameFlow는 각 시스템의 세부 기능을 직접 수행하지 않는다.

GameFlow의 주요 책임은 **현재 게임 단계와 단계 전환 관리**이다.

예:

- Report
- DrivingToPatient
- Pickup
- Transporting
- Result
- GameOver

정상 흐름:

Report  
→ NavigateToPatient  
→ Pickup  
→ Transporting  
→ HospitalArrival  
→ Result  
→ MissionReset  
→ Report

실패 흐름:

Transporting  
→ PatientDied 또는 FatalCollision  
→ GameOver  
→ WorldReset  
→ New Seed  
→ New Map  
→ Report

### 결과 평가

병원 도착 시 확정된:

- ECG 상태
- 충돌 횟수

를 기준으로 별을 계산한다.

- 충돌 0 + Green → ★★★
- 충돌 0 + Yellow → ★★★
- 충돌 0 + Red → ★★
- 충돌 1 + Yellow → ★★
- 충돌 1 + Red → ★
- 충돌 2 → Game Over
- FatalCollision → Game Over

### 성공 후

결과 UI 종료  
→ 도시 유지  
→ 미션 데이터 Reset  
→ 새로운 상황 보고

### 실패 후

GameOver  
→ 현재 미션 정리  
→ 기존 도시 제거  
→ 새로운 Seed  
→ 새로운 도시 생성  
→ 새로운 상황 보고

---

# 시스템 책임 기준

데이터의 주인을 명확하게 유지한다.

## GameFlow

담당:

- 현재 게임 단계
- 단계 전환
- 성공 / GameOver 흐름 연결

담당하지 않음:

- ECG 직접 계산
- Navigation 직접 계산
- 차량 AI 이동
- 환자 AI 이동
- 랜덤 맵 직접 생성

## Mission 시스템

담당:

- MissionId
- 현재 환자 위치
- 현재 병원 위치
- 미션 활성 상태
- 미션별 충돌 횟수 또는 결과 계산에 필요한 미션 데이터

동일한 미션 데이터를 여러 시스템에서 각각 복사해 보관하지 않는다.

## PatientPickup

담당:

- 픽업 조건
- 환자 / 구급대원 탑승 이동
- 환자 탑승 상태
- PatientPickedUp 이벤트

## PatientECG

담당:

- 현재 ECG 값
- 자연 감소
- 충돌 피해 적용
- ECG 상태 판정
- Flatline
- PatientDied 이벤트

## Navigation

담당:

- 실제 도로 데이터 기반 경로 계산
- 현재 목적지
- UI가 사용할 경로 데이터

## Traffic / Pedestrian

각자의 이동과 행동만 담당한다.

GameFlow 또는 Mission 시스템의 세부 로직을 대신 처리하지 않는다.

# 아키텍처 기준

작업 전 필요한 범위에서 다음 순서로 판단한다.

1. 기존 시스템 확인
2. 현재 클래스 책임 확인
3. 재사용 가능한 코드 확인
4. 필요한 클래스 결정
5. 데이터 흐름 결정
6. 자료구조 결정
7. 구현
8. 테스트
9. 최적화

God Class를 만들지 않는다.

반대로 작은 기능마다 클래스를 만들어 스크립트 수를 과도하게 늘리지 않는다.

상속보다 컴포지션을 우선 검토한다.

Interface는 서로 다른 구현체가 동일한 행동 규칙을 공유해야 할 때만 사용한다.

관련 없는 시스템을 작업 단계마다 전체 리팩터링하지 않는다.

# 성능 기준

특히 다음 시스템에서는 반복적인 전체 탐색을 피한다.

- 차량 AI
- 차선 검색
- 교차로
- 네비게이션
- 시민 AI
- 사이렌 주변 반응

자주 수행되는 작업은 가능한 다음 순으로 검토한다.

O(1)  
→ O(log n)  
→ O(n)

Lane의 Left / Right / Next 같은 관계는 직접 참조를 우선한다.

반복적인 `Find`, `FindObjectOfType`, 전체 Scene 검색을 사용하지 않는다.

`GetComponent` 결과는 반복 사용되는 경우 캐싱한다.

불필요한 Update를 만들지 않는다.

매 프레임 계산할 필요가 없는 기능은 이벤트 또는 상태 변경 시 실행한다.

AI 개체 수가 증가해도 동일 데이터를 각 AI가 반복해서 전체 검색하지 않도록 한다.

# 코드 규칙

- 정상 동작 우선
- 클래스 책임 명확화
- 안정성 확인
- 중복 코드 최소화
- 불필요한 변수 / 함수 / 클래스 제거
- 불필요한 public 사용 금지
- Inspector 값은 `[SerializeField] private` 우선
- 단, 명시적으로 public 수정값이 요구된 항목은 요구사항을 우선
- 함수 하나는 가능한 하나의 역할
- null 확인
- 초기화 순서 확인
- 이벤트 중복 구독 방지
- Coroutine 중복 실행 방지
- 파괴되거나 비활성화된 객체 참조 확인
- 불필요한 Update 제거
- 반복적인 전체 탐색 제거

클래스 바로 위:

`/// <summary>`로 클래스의 역할을 설명한다.

함수 바로 위:

`//`로 함수 역할을 짧게 설명한다.

함수 내부에서는 상태 변경 또는 중요한 데이터 흐름에만 필요한 주석을 작성한다.

코드만 읽어도 알 수 있는 내용은 주석으로 반복하지 않는다.

# 매우 중요한 작업 방식

2~14단계를 한 번에 구현하지 않는다.

현재 요청받은 **한 단계만 구현한다.**

다음 단계까지 미리 구현하거나 예상 기능을 추가하지 않는다.

단, 다음 단계에서 연결할 수 있도록 현재 단계의 연결 지점은 고려한다.

기존 시스템으로 해결할 수 있으면 새 시스템을 만들지 않는다.

작업과 직접 관련된 파일을 우선 확인하고 불필요한 프로젝트 전체 탐색을 반복하지 않는다.

테스트도 변경된 기능과 영향받는 범위를 우선 검증한다.

공용 기반 시스템을 수정했을 때만 필요한 범위의 회귀 검증을 추가한다.

작업 완료 후 짧게 다음을 보고한다.

1. 변경된 파일
2. 핵심 구현 내용
3. 테스트 결과
4. 남은 문제
5. 다음 단계 연결 지점
6. 추천 Git Commit 제목

Git Commit / Push는 절대 하지 않는다.
