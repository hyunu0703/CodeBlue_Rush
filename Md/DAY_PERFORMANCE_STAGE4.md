# 누적 실적 4단계 구현 결과

- 작업일: 2026-10-28
- 범위: GamePlay 후송 결과와 하루 완료 저장만 구현했다. 5단계 이후는 진행하지 않았다.
- 환경: Windows, Unity 6000.3.23f1, Input System 1.20.0, URP 17.3.0, Test Framework 1.6.0, uGUI 2.0.0. 버전·패키지·프로젝트 설정은 유지했다.

## 변경 내용과 완료 조건

| 완료 조건 | 구현·검증 결과 |
| --- | --- |
| 병원 인계 결과 | 기존 병원 도착 감지를 유지하면서 즉시 Waiting으로 이동하던 부분을 결과 단계로 바꿨다. 인계 시 입력·HP 감소·충돌 기록을 중단하고 차량을 잠근다. |
| 고정된 기록 | `MissionResult`가 출동 시 진행 원본, 실제 HP, 저속·고속 횟수, 당일 점수와 다음 진행 후보를 한 번 확정한다. 결과 대기·중복 인계 호출·저장 실패에서 다시 계산하지 않는다. |
| 결과 표시 | GamePlay의 기존 MissionSafeArea 아래 결과 패널을 추가했다. 일차·잔여 HP·환자 상태·사고 여부·저속·고속 횟수·당일 실적·이번 날을 포함한 누적 후보를 표시한다. |
| HP 계산과 표시 | `PatientHealth.HealthPercent` 읽기 전용 API로 실제 백분율을 읽는다. 기존 피해 로직은 유지하고, 계산·최종 1회 반올림·표시 내림·상태 경계는 기존 `PerformanceRules`를 재사용한다. |
| 확인 전 상태 | 결과 화면만으로 파일이나 현재 진행은 바뀌지 않는다. 확인 전 종료하면 원래 일차·누적 실적으로 재시작한다. 기존 시드는 저장하지 않고 새 출동 시 기존 랜덤 생성 절차를 실행한다. |
| 저장 성공 후 진행 | 확인 버튼에서 고정 후보를 `GameProgressSession.TrySave`로 저장한다. 성공해야 현재 진행을 교체하고 Waiting으로 이동한다. 일반 일차는 다음 날 Ready, 5의 배수 종료는 다음 날 EvaluationPending을 함께 저장한다. |
| 저장 실패·재시도 | 파일 쓰기 실패 시 결과 패널에 오류와 다시 시도를 표시한다. 기존 파일·현재 진행·결과 후보를 유지하며 같은 후보를 재시도한다. |
| 중복 반영 방지 | 결과 단계·저장 중 플래그로 재진입을 차단한다. 출동 원본과 현재 진행이 달라졌으면 덮어쓰지 않는다. 성공 후에는 완료 단계로 바꾸고 확인 입력을 막는다. 저장 중 재진입·연속 클릭·인계 재호출을 검증했다. |
| 기존 기능 | 요청 수락·출동·맵 생성·픽업·구출 컷신·HP 감소·기존 충돌 물리는 유지한다. HP 0 이후에도 후송을 계속하며 병원 결과 확인으로 하루를 완료한다. |

`MissionController`가 결과 단계와 저장 입력을 관리하고 `MissionResult`는 변경되지 않는 데이터와 표시 문구를 맡는다. `GamePlay.unity`에 패널·본문·저장 안내·확인 버튼·버튼 문구를 직접 연결했다. 런타임 내비게이션이나 주행 UI가 확인 버튼을 가리지 않도록 결과 표시 시 안전 영역과 결과 패널을 위로 배치한다. 별도 인스펙터 수동 설정은 없다.

Start를 거치지 않고 Waiting이나 GamePlay를 직접 실행한 경우에도 GamePlay 진입에서 기존 저장을 확인한다. 읽기 실패·손상은 초기화하지 않고 Start로 돌아가며, 기존 Start의 오류·재시도 진입을 사용할 수 있다. 일반 진행이 아니면 Waiting으로 돌아간다.

6일차 등의 평가 대기는 기존 2단계의 Waiting 요청 차단까지만 연결한다. 평가 통과·해고·재시작 UI와 Waiting 누적 안내는 5단계다. 백그라운드 전체 일시정지는 6단계이며 이번 범위에 포함하지 않았다.

## 실제 검증

원본 프로젝트가 열려 있어 동일 버전의 격리 복사본을 사용했다. EditMode Test Runner의 `EnterPlayMode`로 실제 씬과 버튼을 실행했다. 사용자 저장 경로 대신 테스트 소유 파일을 연결했고, 저장 작업은 실제 `ProgressStore`의 파일 읽기·임시 쓰기·교체를 사용했다. 저장 중 재진입 관찰용 래퍼는 실제 쓰기 전에 같은 확인 버튼을 다시 호출했다.

주 검증은 총 89개 중 80개 통과·9개 기존 실패다. 별도 프로세스 재실행 검증 4개를 합하면 이번 검증 항목은 93개 중 84개 통과·9개 기존 실패다. 새 컴파일 오류·NullReferenceException·MissingReferenceException은 관찰되지 않았다. 저장 실패·손상 읽기 테스트의 의도한 경고와 기존 Unity 라이선스·종료 진단은 로그에 남아 있다.

실제 씬 검사 중 UI 수치 사례는 환자 HP·충돌 횟수와 후송 단계만 주입하여 결과를 만들었다. 실제 픽업·사망 후송·차량 접촉 연동은 별도로 수행했다. 이들 검사에서도 이동은 순간이동으로 단축했으므로 일반 운전 플레이나 모든 랜덤 맵 검증으로 해석하지 않는다.

영구 추가 테스트는 `Assets/Scripts/Editor/MissionResultTests.cs`와 메타다. 삭제된 `PerformanceRulesTests.cs`·`ProgressStoreTests.cs`·`MissionPerformanceTests.cs` 및 메타는 복원하지 않았다. 실제 씬·재실행 검증 소스는 무시되는 복사본에만 두고 로그·XML은 `.utmp/PerformanceStage4/`에 기록했다.

## 변경 범위와 미검증

기존 Assets·Packages·ProjectSettings의 SHA-256 비교에서 변경된 기존 파일은 `GamePlay.unity`, `MissionController.cs`, `PatientHealth.cs` 3개다. 새 결과 데이터·테스트 소스와 메타를 추가했으며 기존 메타·저장 형식·패키지·설정·Start·Waiting 씬·충돌 물리는 유지했다.

실제 WebGL·모바일 브라우저의 빌드·페이지 종료 영속성과 육안 렌더링은 미검증이다. UI 검증은 Editor에서 문구·텍스트 넘침·배치 좌표·입력 레이캐스트를 검사한 범위다.

수동 확인은 Start→수락·출동→픽업→병원 순서로 진행한다. 병원 도착 후 결과가 유지되고, 확인해야 다음 날 Waiting으로 이동하는 것이 기대 결과다. 5일차 완료 후에는 6일차 평가 대기에서 요청이 차단되며, 평가를 진행하는 화면은 5단계에서 연결한다.
