# 누적 실적 준비 단계·1단계 구현 결과

- 작업일: 2026-10-28
- 범위: [구현 계획](DAY_PERFORMANCE_IMPLEMENTATION_PLAN.md)의 준비 단계와 1단계만 수행했다.
- 기준: Unity 6000.3.23f1, Input System 1.20.0, URP 17.3.0, Test Framework 1.6.0, Windows Editor. 기존 WebGL 대상 설정을 유지했으며 WebGL 빌드는 수행하지 않았다.

## 1. 변경 내용과 완료 조건

| 항목 | 구현 및 확인 결과 |
| --- | --- |
| 준비 단계 | 버전·참조·기존 테스트를 확인하고, 새 코드 없는 검증 복사본에서 기준 테스트와 기존 출동·후송 흐름을 실행했다. 기존 실패 9개를 분리해 기록했다. |
| 실적 계산 | 실제 HP 1%당 1점, 생존 무사고 30점, 저속 2점·고속 10점 감점, 하한 0과 사망 0점을 구현했다. |
| 반올림·표시 | 최종 1회 사사오입, HP 소수 첫째 자리 내림, 0.1% 미만 생존과 사망 구분을 구현했다. |
| 상태·충돌 판정 | 실제 HP의 70·30·0 경계, 접촉 법선의 최대 상대 속도와 40km/h 경계를 구현했다. 실제 차량 충돌 이벤트 연결은 하지 않았다. |
| 진행 상태 | 현재 일차·누적 실적·평가 구간·일반 진행·평가 대기·해고를 구현했다. 하루 완료 시 다음 일차로 이동하고 매 5일 완료 시 평가를 대기시킨다. |
| 누적 목표 | `200k + 10k(k - 1)`로 200·420·660·920점 등을 계산한다. 통과 후 실적을 유지하며, 구간 기준 요구량을 별도 통과 조건으로 사용하지 않는다. |
| 중복 처리 | 이미 완료한 일차·평가 번호와 상태가 맞지 않는 요청을 거부한다. 일반 진행 중 재시작은 허용하지 않고 해고 상태에서만 초기화 후보를 만든다. |

진행 객체는 원본을 변경하지 않고 `TryCompleteDay`, `TryCompleteEvaluation`, `TryRestart`에서 다음 상태 후보를 반환한다. 실패하면 원본을 반환한다. 하루 완료에는 완료 일차, 평가 완료에는 평가 구간 번호를 전달한다. `TryCompleteEvaluation`의 성공 반환은 평가 처리를 뜻하며, 합격 여부는 다음 상태가 일반 진행인지 해고인지로 구분한다.

이 방식은 나중에 저장 성공 후 후보를 실제 진행 상태로 채택하기 위한 경계를 제공하지만, 이번 단계에 저장 코드나 저장 서비스는 구현하지 않았다. 정적 전역 진행 인스턴스, 씬 자동 실행과 UI 연결도 추가하지 않았다.

기존 9개 실패는 `VehicleImpactTests.CreateInstance_ModelMassAndInertia_PersistThroughPoolReuse`의 차종별 기대 질량이 현재 교통 질량 배율 1.2를 반영하지 않아 발생했다. 예를 들어 Avante의 테스트 기대값은 1,250kg이나 현재 코드는 1,500kg이다. 새 소스가 없는 기준 실행에서도 동일하게 실패했으며 이번 범위에서 수정하지 않았다. 따라서 전체 기존 테스트가 모두 통과했다고 보고하지 않는다.

원본 프로젝트는 다른 Unity 인스턴스가 사용 중이어서 종료하거나 잠금을 지우지 않고 검증 복사본을 사용했다. 제한된 실행에서 WMI·라이선스 접근 문제, 긴 물리 경로의 패키지 UI 리소스 import 오류를 관찰했다. 최종 실행은 검증 복사본만 임시 P: 경로로 연결해 수행했고 연결은 실행 후 해제했다. 최종 로그에는 해당 경로 import 오류와 C# 컴파일 오류, NullReferenceException·MissingReferenceException이 관찰되지 않았다. 라이선스 접근 토큰 및 디버거 포트 안내는 남았지만 테스트 결과 파일은 생성되었으므로 로그 전체를 무오류라고 분류하지 않는다.

## 4. 실행으로 확인한 주요 규칙

- HP 72.46% 무사고는 102점, 72.50% 무사고는 103점이다. 짝수 쪽 반올림이 아닌 0.5 올림을 확인했다.
- 실제 HP 69.99%는 위험이며 표시 69.9%, HP 0.04%는 생존·표시 0.1% 미만, HP 0은 사망·실적 0점이다.
- 39.99km/h는 저속, 정확히 40km/h는 고속이며 접선 방향 속도는 법선 충격에 더하지 않는다.
- 매일 102점으로 확정한 5일의 누적은 510점이며 원본 소수를 합쳐 512점으로 바꾸지 않는다.
- 5일차 누적 250점과 다음 5일 170점을 합친 420점으로 두 번째 평가를 통과한다.
- 목표를 미리 넘었어도 하루를 생략하지 않고, 평가 통과 후 초과 실적을 포함한 전액이 유지된다.
- 계산상 하루 최대 130점을 계속 얻는 사례도 같은 공개 완료 경로로 진행해, 누적 목표와 초과분 유지가 후반까지 맞는지 확인했다. 실제 플레이에서 이 점수를 얻었다는 의미는 아니다.

## 5. 미구현·미검증과 후속 범위

- 2단계 이후의 로컬 저장·복원·실패 재시도, Start 연결, 실제 충돌 기록, 결과 UI, Waiting 누적 평가·해고 UI, 백그라운드 일시정지는 아직 구현하지 않았다.
- 새 상태 모델은 현재 게임에서 자동 호출되지 않는다. 기존 플레이 흐름과 화면은 유지되며 새 컴포넌트 연결이나 수동 인스펙터 설정도 이번 단계에는 필요하지 않다.
- WebGL 빌드·브라우저 영속 저장·모바일·시각적 UI 검수·실제 전체 경로 운전·거리별 밸런스 측정은 미검증이다.
- 기존 화면 수동 확인은 Unity 6000.3.23f1에서 Start를 실행하고 시작하기→요청 확인→수락→출동하기→실제 주행으로 픽업→컷신→병원 후송 순서로 진행한다. 아직 날짜·결과 UI를 연결하지 않았으므로 병원 도착 후 기존대로 Waiting으로 복귀하는 것이 기대 결과다.
- 준비 단계와 1단계의 계산·진행 완료 조건은 구현 및 해당 범위의 실행 검증을 마쳤다. 기존 테스트 실패 9개는 남아 있으며, 이후 단계는 별도 요청 전 진행하지 않는다.
