# 회전 출구와 긴 직선의 교통 보충

## 원인과 적용 내용

`RoadTrafficController`의 생성 및 회수 정책을 수정했다. 씬, 프리팹, 패키지 및 직렬화된 Inspector 값은 변경하지 않는다.

1. 플레이어의 현재 차선을 연결된 직선 구간까지 전부 생성 후보에서 제외하던 조건을 제거했다. 우측 차선으로 주행하더라도 같은 차선의 안전한 위치에는 차량을 배치한다. 기존 플레이어 주변 생성 금지 반경, 차체 간격과 픽업 구역의 생성 제한은 유지한다.
2. 현재 도로와 바로 이웃한 도로에서 끝나던 후보 탐색을 연결된 직선 구간의 탐색으로 변경했다. 탐색은 활성 도로와 반경 안에 한정하고 교차로를 넘지 않는다. 기본 보충 반경은 최소 두 타일을 확보한다.
3. 멀리 있거나 시야 뒤로 빠진 차량이 주변 차량 수를 채우지 않게 했다. 다음 교차로에 미리 배치할 차량과 별도로 근거리 목표를 전체 허용량의 절반 이상 확보한다. 현재 차종별 두 대 제한에서는 전체 최대 18대 중 근거리 목표가 9대다. 전체 허용량과 차종별 제한은 늘리지 않는다.
4. 주행 중 근거리 보충은 실제 이동 방향의 화면 밖을 우선한다. 현재 타일의 뒤쪽 빈자리만 채우는 현상을 막으며, 화면 안의 기존 차량을 보충 목적으로 회수하지 않는다. 새 맵의 최초 배치는 기존과 같이 화면 안에서도 허용한다.

## 검증 조건

- Unity 6000.3.23f1, Editor/Standalone, 세로 카메라 비율 480:854, 원본 GamePlay의 직교 카메라 크기 4를 사용한다. Input System 1.20.0, URP 17.3.0, Test Framework 1.6.0을 유지한다.
- 사용자가 열어 둔 에디터를 종료하지 않고 `.utmp/WaitingValidation` 복사본에서 컴파일과 Play Mode를 포함한 EditMode 테스트를 실행한다. 복사본의 해당 런타임 스크립트는 원본에 적용한 파일과 동일하다.
- `TrafficCoverageTests.FirstTurnRetainsOuterLaneTraffic`: 4·6차선과 첫 번째·두 번째 좌우회전 조합 8개 시드에서 첫 회전 출구 바깥 차선의 후보 및 실제 배치를 검사한다.
- `TrafficCoverageTests.LongStraightKeepsOffscreenTrafficSupply`: 같은 8개 시드에서 두 번째 교차로를 통과해 이전 구간이 반환된 상태로 긴 직선의 6개 위치를 검사한다. 두 타일 앞 보충 후보, 근거리 차량, 화면 밖 생성 및 플레이어 주변 생성 금지 반경을 확인한다.
- `TrafficCoverageTests.DrivingLongStraightDoesNotLeaveAnEmptyBlock`: 4·6차선 두 경로의 두 번째 교차로 뒤 9개 직선 타일을 이동한다. 실제 물리 시간이 전진할 때마다 6유닛/초 기준의 고정 스텝 간격으로 차체와 카메라를 이동시키고 화면 좌표 안의 AI 차량을 센다. 두 타일(25.08유닛) 이상 연속으로 차량이 전혀 보이지 않는 공백이 없는지 검사한다. 교통 배치만 검사하기 위해 시험 구급차와 AI의 물리 충돌은 무시한다.
- 기존 `TrafficPickupTests`와 `MissionRoadGenerationTests`를 함께 실행한다. 맵 단독 Play Mode 테스트는 MissionController를 비활성화해 출동 승인 없는 GamePlay의 자동 복귀와 분리한다.

수정 전 코드에서는 바깥 차선 제외 및 이웃 도로 너머의 후보 누락이 각각 재현됐다. 결과 파일은 `.utmp/traffic-coverage-before.xml`과 `.utmp/traffic-coverage-after.xml`이다.

2026-10-25 최종 결과: 컴파일 성공, 선택한 회귀 테스트 **25개 모두 통과**(실패·건너뜀 0개, 실행 시간 약 45.4초). 새 교통 검사 3개, 기존 픽업 검사 19개와 도로 생성 검사 3개를 포함한다. 변경한 소스가 검증 복사본과 같은지 및 `git diff --check` 통과도 확인했다. 해당 실행 로그에서 C# 컴파일 오류, NullReferenceException 및 MissingReferenceException은 관찰되지 않았다.

실제 키·터치 입력으로 전체 미션을 완주하는 확인, 모바일 WebGL 빌드, 화면 이미지의 시각적 검수와 성능 측정은 별도다. 테스트는 모든 시드에서 매 순간 모든 차선에 차량이 있음을 보장하지 않는다.

## Unity에서 확인하기

1. Play Mode를 종료하고 스크립트 컴파일을 기다린다. 추가 Inspector 설정은 필요 없다.
2. Start 또는 Waiting에서 미션을 수락하고 출동한다.
3. 첫 교차로에서 좌회전하는 경로와 우회전하는 경로를 각각 주행한다. 플레이어가 있는 우측 차선도 전방에 차량이 생성되는지 확인한다.
4. 두 번째 교차로를 벗어나 다음 교차로까지 이동한다. 현재 구간의 교통이 계속 보충되고 화면 안에서 차량이 갑자기 나타나거나 사라지지 않는지 확인한다.
5. 픽업 주차 구역이 생성 차량으로 막히지 않고, 픽업 후 후송 경로에서도 교통이 유지되는지 확인한다.
