# 건물 배치 규칙

- 건물 원본의 XY Scale은 2를 유지한다. 공간에 맞추는 자동 축소는 하지 않는다.
- 차도와 보도를 제외한 교차로의 건물 줄을 먼저 간격 0으로 채운다. 마지막 건물이 직선 프리팹 경계를 걸쳐도 된다.
- 모퉁이에서는 두 축의 건물 줄이 겹치지 않도록 담당 면을 나눠 서로 맞댄다.
- Apartment의 `Allow Intersection`은 꺼져 있다. 이미지와 콜라이더를 포함한 외곽이 교차로에 일부라도 들어가면 제외한다.
- 교차로 배치를 고정한 뒤 다음 교차로까지의 직선 전체 길이를 계산한다. 남는 길이를 건물 사이의 모든 간격에 동일하게 분배한다. 도로 프리팹마다 간격을 따로 계산하지 않는다.
- 직선 간격은 GamePlay의 Ambulance BoxCollider2D의 짧은 축을 Map Root 좌표로 변환한 길이보다 작아야 한다. 회전한 AABB 폭을 사용하지 않는다.
- 계산 오차를 위한 여유를 포함해 간격 상한은 차체 폭의 99.9%다. 현재 차체 폭은 0.3135유닛이며 상한은 0.3131865유닛이다.
- 다음 교차로가 없는 맵 시작·끝에서는 상한을 초과하는 잔여 길이를 맵 바깥쪽 끝에만 남긴다. 교차로 사이에는 이 예외를 적용하지 않는다.
- 후송 경로가 길어지면 기존 교차로 건물의 원본과 변환은 보존한다. 연결된 직선은 전체 길이를 기준으로 다시 계산하므로 건물 위치와 종류가 바뀔 수 있다.
- 경계를 걸친 건물은 닿는 도로가 하나라도 활성 상태면 한 번만 유지한다. 관련 도로가 전부 반환되면 원본별 풀로 반환한다.
- 조건을 만족하는 배치를 찾지 못하면 오류를 반환하고 이전 맵을 보존한다. 교차로에 틈을 남기거나 간격 상한을 넘기는 대체 처리는 하지 않는다.

## 시작 소방서

- 구급차는 미션마다 소방서 앞 첫 직선 도로의 중앙선 오른쪽 1차로 중앙에서 북쪽을 향해 정지 상태로 출발한다. 도로 시작 경계에서 0.5유닛 안쪽에 중심을 두며, 현재 12.54유닛 도로 기준 맵 로컬 좌표는 (0.423, -5.77)이다. 4·6차선과 미션 시드에 관계없이 같은 기준을 사용하고 후송 확장에서는 차량을 이동하지 않는다.
- 기존 `Assets/Prefabs/Building/FireStation.prefab`의 Z 회전을 -180도로 설정하고 GamePlay의 `MissionSystem > MissionMapGenerator > Start Fire Station`에 연결한다. `FireStationStart`는 사용하지 않고 보관한다. 기존 소방서 이미지와 GUID는 유지한다.
- XY Scale 6과 이미지 PPU 1266.6075731을 유지한다. 월드 크기는 약 5.1492×6.8498유닛이며 일반 저층 건물 가로·세로의 약 3배다.
- 미션 생성 시 첫 도로의 아래쪽 끝에서 0.16유닛 떨어진 바깥에 중앙 정렬한다. 현재 첫 도로 12.54×12.54 기준 소방서 중심은 맵 로컬 약 (0, -9.8549), 위쪽 외곽은 Y=-6.43이다. 처음 카메라 화면 밖에 놓는 선택을 따른다.
- 도로·차량 생성 범위를 자르지 않는다. 맵 시드 후보를 검사할 때 소방서와 겹치는 도로 타일을 제외해 뒤로 돌아온 도로나 교차로 분기가 소방서를 관통하지 않게 한다.
- 일반 건물은 회전 0 검증을 유지한다. 시작 소방서만 Z 회전 0/-180을 허용하며 생성·풀 복원 시 원본 프리팹의 회전을 곱해 -180이 초기화되지 않게 한다.
- 도로 타일과 직접 겹치지 않아도 첫 도로를 스트리밍 소유자로 등록한다. 기존 건물의 바닥·정적 충돌·풀을 사용하고 후송 확장과 역주행 복원 시 위치·회전·크기를 유지한다.
- `Start Side Building`에는 기존 Apartment 프리팹을 연결한다. 소방서 좌우에 Scale 2를 유지한 아파트를 한 채씩 붙인다. 두 건물의 위쪽은 소방서 위쪽과 맞추고 첫 도로를 복원 소유자로 공유한다.
- 아파트와 기존 도로변 건물 사이의 인도에는 `StartBoundary` 정적 BoxCollider2D를 연결한다. 실제 건물 콜라이더끼리 0.01유닛 겹치도록 이어 틈을 막되 도로변 건물과 겹치는 폭만 사용하므로 차도와 기존 보도 안쪽을 침범하지 않는다. 이 연결부는 소방서 옆 건물의 자식으로 풀에 반환하며, 일반 아파트로 재사용하면 비활성화한다. 후송 확장 시 현재 도로변 건물 배치에 맞춰 연결부를 다시 계산해 두 채만 유지한다.
- 양옆 건물 추가 후 검증: Unity 6000.3.23f1 참조의 런타임·에디터 C# 빌드에서 경고 0개·오류 0개. 별도 수학 대역 계산 644건·3,464,760회 검사를 통과했다. 양옆 두 채와 소방서의 틈이 구급차 충돌 폭의 절반 미만인지, 연결부가 두 건물의 실제 콜라이더와 겹치는지, 도로·보도 침범이 없는지, 후송 후 중복이 없는지 확인했다. 실제 Unity 물리 실행 결과와 구분한다.
- 2026-10-28 별도 .NET 계산 검증: 실제 배치 소스와 기존 경량 Unity 수학 대역으로 644건·3,352,278회 검사 통과. 4·6차선, 1~9칸 직선, T자 뒤 확장 및 픽업 32건·후송 32건을 확인했다. 절대 위치, 도로 밖 소유자 등록, 중복·건물 겹침 방지를 검사했으며 엔진 실행 검증과 구분한다.
- 수동 확인: GamePlay에서 미션을 생성하고 첫 도로 아래쪽 끝 바깥에 기존 FireStation이 Z=-180, Scale=(6,6,1)로 한 채 생성되는지 확인한다. 첫 화면 밖이므로 Scene 뷰 또는 구급차 후진으로 확인한다. 후송 확장 뒤 시작 구간으로 돌아왔을 때 같은 위치·회전으로 한 채만 복원되고, 접근한 구급차가 소방서 콜라이더에 충돌해야 한다. 실제 플레이 외관·물리 동작은 미검증이다.
- 탈출 방지 확인: 구급차를 소방서 왼쪽·오른쪽 인도 틈으로 각각 후진시켜 아파트와 연결 충돌 영역에 막히는지 확인한다. 후송 경로를 생성하고 다시 시작 구역으로 돌아온 뒤에도 같은 동작을 확인한다. 일반 도로의 차도 주행은 방해받지 않아야 한다.

## 건물 주변 바닥

- 생성된 건물마다 이미지와 충돌 영역을 합친 외곽에서 사방으로 최소 0.64 Map Root 로컬 유닛의 바닥 여백을 확보한다.
- 기존 4차선 직선 도로 이미지의 인도 안쪽 40×40px 구간을 공유한다. 원본 PPU를 유지한 반복 타일로 인도의 색상과 줄눈을 사용한다.
- 바닥 외곽을 맵 기준 타일 격자에 맞춰 겹치는 바닥의 무늬를 일치시킨다. 건물이 회전하거나 좌우 반전되어도 바닥의 방향과 타일 크기는 유지한다.
- 바닥은 도로보다 한 단계 아래에 그리며 별도 콜라이더는 추가하지 않는다. 건물의 배치와 간격 계산에는 영향을 주지 않는다.
- 바닥은 건물의 자식으로 생성하고 같은 인스턴스를 재사용한다. 공유 건물의 스트리밍, 풀 반환 및 파괴를 함께 따른다. 씬과 프리팹의 수동 연결은 필요 없다.

`BuildingGroundTests`는 실제 건물 프리팹 전체를 2개 배치 축·좌우 반전 조합으로 검사하며, 외곽 여백과 타일 격자, 렌더 순서, 비활성화 및 중복 생성 방지를 확인한다. 2026-10-28 Windows에서 Unity 6000.3.23f1 참조를 사용하는 런타임·에디터 C# 프로젝트를 새 테스트 파일까지 포함해 .NET SDK로 빌드했고 경고 0개, 오류 0개였다. Unity 배치 실행은 초기화 단계에서 종료 코드 1로 끝나 테스트 결과 파일이 생성되지 않았다. 첫 시도에는 라이선스 연결 및 WMI 오류가 기록되었고, 라이선스 연결이 성공한 재시도도 종료되어 종료 원인은 확정하지 못했다. 테스트 실행과 GamePlay 외관은 미검증이다.

수동 확인: GamePlay에서 서로 다른 시드의 미션을 시작하고 직선 양쪽·T자·십자 교차로의 건물 주변에 회색 인도 무늬와 여백이 표시되는지 확인한다. 후송 경로를 확장하고 지나온 구간으로 되돌아갈 때 건물과 바닥이 함께 복원되며 차도와 기존 인도를 가리지 않아야 한다.

구현 근거: Unity 6.3의 [Sprite.Create](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Sprite.Create.html)로 기존 텍스처의 일부 영역을 공유하고, [SpriteRenderer.size](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/SpriteRenderer-size.html)와 Tiled 모드로 바닥 영역을 채운다. 공식 API 근거와 프로젝트 실행 검증은 구분한다.

## 검증

`MissionBuildingLayoutTests`는 실제 에셋을 사용해 교차로 구간 전체의 외곽 연결, 1·2·9칸 직선의 균등 간격, 좌우 반전, 크기 유지, 겹침과 차도 침범, 아파트 제외, 시드 재현 및 공유 건물 스트리밍을 검사한다.

별도 .NET 계산 검증은 Unity 생명주기와 물리 실행을 검증하지 않는다. Unity Editor 6000.3.23f1의 배치 테스트는 현재 시작 단계에서 종료되어 실행 결과를 얻지 못했다. GamePlay에서 새 미션을 생성해 교차로의 빈틈, 직선의 균등 간격, 후송 확장과 역주행 복원 동작을 직접 확인해야 한다.
2026-10-27 별도 .NET 계산 검증: 도로 13종·4방향, 4·6차선의 1~9칸 직선, 실제 시드 기반 픽업·후송 조합 총 2,334건 및 47,843,937회 검사 통과. 실제 프리팹의 이미지 크기·PPU·스케일·콜라이더 규격을 읽고 런타임 배치 코드를 경량 수학 대역과 함께 실행한 결과이며 Unity 엔진 실행 검증과 구분한다. C# 런타임·에디터 프로젝트 빌드는 경고 0개, 오류 0개다.
