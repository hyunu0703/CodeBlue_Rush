# CodeBlueRush 도시 도로 설계 가이드 — WebGL 모바일 최적화 리뉴얼

> 기준 프로젝트: Unity 6000.3.23f1 / 2D / WebGL / 모바일 / 480×854
>
> 최우선 제약: **최종 웹사이트 배포 용량은 절대로 100 MB를 초과하지 않는다**
>
> 작업 우선순위:
>
> **1순위 용량 제한 → 2순위 연산 최적화 → 3순위 구현 완료**
>
> 본 문서는 기존 도시 도로 설계안을 유지하면서, 위 우선순위에 맞게 구현 규칙을 리뉴얼한다.

---

# 1. 절대 규칙

## 1.1 100 MB는 하드 실패 기준이다

최종 배포 결과물이 100 MB를 넘으면 기능이 정상 동작하더라도 완료로 인정하지 않는다.

권장 운영 기준:

- 목표: **85 MB 이하**
- 경고: **90 MB 이상**
- 중단 및 재최적화: **95 MB 이상**
- 절대 금지: **100 MB 초과**

현재 배포 폴더 크기는 매 단계 실제 WebGL Release Build 결과를 기준으로 측정한다.

에디터의 원본 PNG 파일 크기만 보고 판단하지 않는다.

---

# 2. 현재 기준점

최신 main 기준 현재 `docs/` 배포 파일은 약 **65.74 MB**이다.

주요 파일:

- `docs/Build/docs.wasm`: 약 48.39 MB
- `docs/Build/docs.data`: 약 16.84 MB
- 기타 Loader / Framework / HTML: 약 0.51 MB

따라서 현재 상태에서:

- 100 MB까지 절대 여유: 약 **34.26 MB**
- 85 MB 목표까지 실사용 여유: 약 **19.26 MB**

도시 제작은 **19 MB 정도의 안전 예산 안에서 끝내는 것**을 기본 목표로 한다.

단, 이후 WebGL Player/Code 최적화로 기본 빌드가 줄어들면 확보된 용량을 도시 리소스 예산에 다시 배분할 수 있다.

# 3. 최종 도시 구조

도시는 6개 구역으로 구성한다.

| 주거지역 | 좌측 상단 | 좁은 2차선, 커브 많음 | 대형 아파트 단지 | 저속·코너 운전 |
| 상업지역 | 중앙 상단 | 4차선, 교차로 많음 | 중앙 광장 + 대형 상가 | 신호·교통량 대응 |
| 병원지역 | 우측 상단 | 넓은 진입도로 | 대형 종합병원 | 최종 목적지 |

구역 구조와 플레이 성격은 유지한다.

최적화를 위해 구역 수를 늘리지 않는다.

# 4. 도로 최적화 핵심 원칙

## 4.1 도로 하나마다 별도 이미지를 만들지 않는다

도로는 가능한 한 **재사용 가능한 최소 타일 세트**로 제작한다.

필수 기본 세트 예시:

- 2차선 직선
- 4차선 직선
- 기본 커브
- T자 교차로
- 십자 교차로
- 횡단보도
- 차선 표시
- 인도
- 다리
- 특수 진입로

동일 구조의 동/서/남/북 이미지를 각각 제작하지 않는다.

가능하면 **한 이미지를 90° 회전 또는 좌우 반전하여 재사용**한다.

---

## 4.2 도로 이미지는 레이어 조합을 우선한다

큰 완성형 도로 PNG를 많이 만드는 방식보다 다음 레이어를 조합한다.

```text
아스팔트 기본 타일
+
차선 / 화살표 / 횡단보도
+
인도 / 연석
+
교통 소품
```

이 방식으로 같은 아스팔트와 표시 리소스를 여러 도로에 재사용한다.

---

## 4.3 한 장의 거대한 전체 도시 이미지를 사용하지 않는다

전체 맵을 하나의 초대형 PNG로 제작하는 방식은 금지한다.

이유:

- 원본 및 빌드 데이터 증가
- 텍스처 메모리 증가
- 작은 수정에도 전체 이미지 재제작 필요
- 동일 도로/건물 재사용 불가

최종 도시는 **타일 + 반복 Sprite + 소수 랜드마크** 조합으로 만든다.

---

## 4.4 도로 시각 요소와 주행 데이터는 분리한다

도로 Sprite가 Navigation, Lane, AI 로직을 직접 담당하지 않는다.

```text
Visual
- Tilemap
- Sprite
- Road Marking

Logic
- Lane 데이터
- Navigation 노드
- Trigger
- Traffic Signal
```

시각 리소스 변경 때문에 도로 알고리즘을 다시 계산하지 않도록 한다.

---

# 5. 도로 렌더링 구조

권장 구조:

```text
City
├─ GroundTilemap
├─ RoadBaseTilemap
├─ RoadMarkingTilemap
├─ SidewalkTilemap
├─ StaticDecoration
├─ Buildings
└─ DynamicObjects
```

도로와 인도는 가능하면 Tilemap을 사용한다.

목표:

- SpriteRenderer GameObject 수 감소
- 반복 이미지 재사용
- Renderer 관리 비용 감소
- 씬 Hierarchy 단순화

도로 타일마다 MonoBehaviour를 붙이지 않는다.

---

# 6. 도로 이미지 제작 규칙

## 6.1 최대 해상도

480×854 모바일 화면을 기준으로 필요한 픽셀만 사용한다.

권장:

- 일반 도로 타일: 128~256 px 중심
- 큰 교차로: 최대 512 px 권장
- 다리/특수 요소: 512 px 우선
- 1024 px 초과: 실제 화면에서 필요성이 확인된 경우만 허용
- 2048 / 4096 px 도로 이미지: 기본 금지

---

## 6.2 Sprite Atlas

도로 관련 Sprite는 전용 Sprite Atlas에 묶는다.

권장 분리:

- `RoadAtlas`
- `RoadMarkingAtlas`
- `SidewalkAtlas`

Atlas 최대 크기는 우선 **1024~2048** 범위로 제한한다.

한 Sprite가 여러 Atlas에 중복 포함되지 않도록 한다.

---

## 6.3 텍스처 설정

모바일 Web 기준:

- Web Platform Override 사용
- ASTC 지원 환경: **ASTC 8×8 우선 검토**
- ASTC 미지원 범위를 고려해야 하면 ETC2 사용
- Read/Write: Off
- Mip Map: 고정 탑뷰 Sprite는 기본 Off
- 불필요한 Alpha 제거
- 투명 여백 최소화
- 불필요하게 큰 Max Size 금지

로우폴리 명암은 별도 Normal Map이나 Mask Map 대신 **기본 Sprite에 직접 표현**한다.

# 15. 연산 최적화 규칙

## 15.1 정적 도로에 Update 금지

다음에는 Update를 사용하지 않는다.

- 도로
- 인도
- 건물
- 장식
- 주차장
- 고정 랜드마크

정적인 오브젝트는 정적인 상태로 둔다.

---

## 15.2 Navigation은 필요할 때만 계산한다

경로 탐색은 다음 시점에만 실행한다.

- 새 환자 목적지 설정
- 환자 픽업 후 병원 목적지 설정
- 경로가 실제로 무효화된 경우

매 프레임 경로 탐색 금지.

---

## 15.3 동적 오브젝트만 활성 범위를 사용한다

차량과 시민은 전체 도시를 항상 시뮬레이션하지 않는다.

플레이어 또는 카메라 주변 일정 범위만 활성화한다.

멀어진 차량/시민은:

- Pool로 반환
- AI 정지
- Physics 비활성

중 하나를 사용한다.

---

## 15.4 Object Pool 사용

다음은 Instantiate / Destroy 반복을 피한다.

- 일반 차량
- 시민
- 충돌 이펙트
- 필요 시 미션 표시

재사용 Pool을 사용한다.

---

## 15.5 Physics2D 단순화

- 정적 건물/장애물: 단순 BoxCollider2D 우선
- 복잡한 PolygonCollider2D 남용 금지
- 필요한 Layer끼리만 충돌
- 도로 시각 Sprite에는 Collider를 붙이지 않음
- 충돌 영역과 시각 영역을 분리

---

# 16. WebGL Release Build 규칙

최종 Release Build는 다음을 기본 목표로 한다.

- Development Build: Off
- Code Optimization: **Disk Size with LTO**
- Compression: **Brotli**
- Decompression Fallback: 서버가 지원하면 Off
- Data Caching: On
- Debug Symbols: Off
- Managed Stripping Level: High
- Strip Engine Code: On
- API Compatibility: .NET Standard 2.1 우선
- IL2CPP Code Generation: Smaller/Faster Build 계열 우선
- Target WebAssembly 2023: 지원 브라우저 검증 후 On
- WebGL Threads: 기본 Off 유지
- 불필요 Package / Plugin 제거

High Stripping으로 런타임 문제가 발생하면 필요한 타입만 `[Preserve]` 또는 `link.xml`로 보존한다.

전체 Stripping 강도를 바로 낮추는 것은 마지막 선택이다.

# 17. 용량 측정 규칙

각 주요 파트 완료 후 Release Build를 한 번 생성한다.

확인 순서:

1. 전체 `docs/` 또는 실제 배포 폴더 크기
2. `.wasm`
3. `.data`
4. Texture
5. Audio
6. Shader / Code
7. 가장 큰 개별 Asset

Unity Editor Log / Build Report에서 가장 큰 에셋부터 최적화한다.

원본 Assets 폴더 크기보다 **실제 빌드 기여 용량**을 우선한다.

---

# 18. 작업 완료 조건

도로 파트는 다음 조건을 모두 만족해야 완료다.

1. 기존 6개 구역의 운전 성격이 유지됨
2. 필수 경로가 모두 연결됨
3. 동일 도로 리소스가 적극적으로 재사용됨
4. 불필요한 방향별 중복 Sprite가 없음
5. 정적 도로에 Update가 없음
6. 실제 모바일 WebGL에서 주행이 정상 동작함
7. Release Build 전체 크기가 내부 예산을 초과하지 않음
8. 100 MB 제한을 위협하면 구현 범위를 줄여서라도 용량을 먼저 해결함

# 19. 최종 판단 우선순위

새 도로 기능 또는 리소스를 추가할 때 항상 다음 순서로 판단한다.

