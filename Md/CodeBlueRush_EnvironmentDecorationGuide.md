# CodeBlueRush NewGamePlay 자연환경 · 공원 배치 가이드

## 1. 문서 목적

이 문서는 `CodeBlueRush`의 `NewGamePlay.unity`에서 도로, 보도, 하천, 건물 배치가 완료된 이후 진행하는 **자연환경 및 공원 꾸미기 작업 기준**을 정의한다.

이번 단계의 목표는 단순히 빈 공간을 장식으로 채우는 것이 아니다.

`Maps.png`의 도시 구성을 기준으로 다음 요소를 적절한 위치와 밀도로 배치하여 전체 도시가 하나의 완성된 맵처럼 보이도록 한다.

- 나무
- 수풀 및 작은 식생
- 공원
- 공원 내부 보행길
- 강변 산책 공간
- 하천 주변 돌
- 녹지 장식

기존 도로와 건물 구조는 현재 상태를 유지한다.

---

# 2. 작업 기준

최신 `main` 기준으로 작업한다.

작업 시작 전에 반드시 다음 파일과 현재 Scene을 확인한다.

```text
Assets/Image/Maps/Reference/Maps.png

CodeBlueRush_MapAssetStyleGuide.md
CodeBlueRush_BuildingPlacementGuide.md
CodeBlueRush_CityRoadDesignGuide.md

NewGamePlay.unity
```

실제 프로젝트에서 경로가 다르다면 파일명을 기준으로 찾아 사용한다.

---

# 3. 기준 우선순위

모든 시각적 판단은 다음 우선순위를 따른다.

```text
1. Maps.png
↓
2. 현재 NewGamePlay.unity
↓
3. CodeBlueRush 관련 가이드 문서
↓
4. 기존 프로젝트 규칙
```

가이드 문서와 `Maps.png`의 표현이 충돌한다면 **Maps.png를 우선한다.**

다만 현재 `NewGamePlay.unity`에서 이미 완료된 도로와 건물 구조를 Maps.png와 조금 다르다는 이유로 다시 변경하지 않는다.

---

# 4. 현재 완료된 구조

현재 `NewGamePlay.unity`에는 다음 구조가 이미 구현되어 있다고 가정한다.

```text
도로
보도
교차로
T자 도로
코너 도로
다리
하천
항구
건물
주차 공간
주요 도시 블록
```

이 구조는 이번 작업에서 **완성된 기반 구조**로 취급한다.

---

# 5. 기존 구조 변경 금지

이번 작업에서 다음 작업을 하지 않는다.

```text
도로 위치 변경
도로 폭 변경
도로 추가 또는 삭제
교차로 구조 변경
T자 도로 구조 변경
다리 위치 변경
하천 형태 변경
건물 이동
건물 크기 변경
건물 교체
주차장 구조 변경
항구 구조 변경
도시 블록 재설계
```

자연환경을 배치하기 위해 기존 구조를 움직이는 방식으로 해결하지 않는다.

현재 존재하는 **빈 공간과 녹지 공간을 활용한다.**

---

# 6. 이번 작업 범위

이번 단계에서 배치하는 대상은 다음과 같다.

```text
나무
수풀
작은 식생
공원
공원 내부 보행길
강변 산책 공간
하천 주변 돌
잔디 및 녹지 장식
```

여기서 말하는 `길`은 기존 차량용 Road가 아니다.

이번 작업의 길은 다음을 의미한다.

```text
공원 산책로
녹지 내부 보행길
강변 산책길
```

차량 Road 시스템이나 Lane 시스템과 연결하지 않는다.

---

# 7. 최종 목표

480×854 Game View에서 보았을 때 다음 영역이 자연스럽게 구분되어야 한다.

```text
도로
건물
녹지
공원
하천
항구
```

동시에 서로 따로 존재하는 것처럼 보이지 않고 하나의 도시로 연결되어 보여야 한다.

목표는 `Maps.png`처럼 다음 흐름을 만드는 것이다.

```text
도로
↓
보도
↓
건물 / 녹지
↓
공원 / 나무
↓
하천 자연환경
```

---

# 8. Maps.png 사전 분석

배치를 시작하기 전에 `Maps.png`를 먼저 분석한다.

다음 항목을 확인한다.

```text
나무가 밀집된 지역
나무가 적은 지역
나무가 일렬로 정돈된 지역
불규칙하게 배치된 자연 구역
건물 사이의 작은 녹지
큰 공원
작은 공원
공원 내부 길
강변 녹지
강변 돌
강변 나무
도시 외곽 녹지
항구 주변 식생
산업지역의 자연물 밀도
```

그 후 현재 `NewGamePlay.unity`에서 대응되는 공간을 찾아 배치한다.

---

# 9. 중요한 배치 원칙

빈 공간이 있다는 이유만으로 모든 공간을 장식으로 채우지 않는다.

다음 기준으로 판단한다.

```text
1. 차량 이동 공간인가?
→ 비워둔다

2. 보행 공간인가?
→ 통행을 방해하지 않는다

3. 건물 가독성을 위해 필요한 여백인가?
→ 일부 비워둔다

4. Maps.png에서 녹지 역할을 하는 공간인가?
→ 자연물을 배치한다

5. 충분히 큰 녹지인가?
→ 공원 후보로 사용한다

6. 하천과 인접한 공간인가?
→ 강변 자연환경 후보로 사용한다
```

---

# 10. 나무 배치 기본 원칙

나무는 이번 자연환경 작업에서 가장 중요한 요소 중 하나이다.

하지만 Scene 전체에 동일한 규칙으로 반복 배치하지 않는다.

지역에 따라 다음 요소를 다르게 한다.

```text
나무 밀도
나무 간격
나무 종류
나무 배치 형태
나무 크기
```

---

# 11. 도시 외곽 나무

Maps.png처럼 도시 외곽은 내부 도시보다 자연물 밀도를 높일 수 있다.

대상:

```text
맵 상단 외곽
맵 왼쪽 외곽
맵 오른쪽 외곽
맵 하단 외곽
```

외곽 나무는 도시 경계를 자연스럽게 보여주는 역할을 한다.

너무 정확한 일렬 형태로 반복하지 않는다.

예:

```text
Tree     Tree
    Tree

Tree        Tree Tree
      Tree
```

---

# 12. 도로변 나무

도로 주변에 충분한 녹지 공간이 있는 경우 나무를 배치한다.

단, 차량 도로와 보도 영역을 침범하지 않는다.

정돈된 도시 지역에서는 다음처럼 일정한 형태를 사용할 수 있다.

```text
Tree    Tree    Tree    Tree
```

자연스러운 녹지 지역에서는 다음처럼 약간 불규칙하게 배치한다.

```text
Tree      Tree
     Tree       Tree
```

모든 도로변을 동일한 패턴으로 만들지 않는다.

---

# 13. 건물 주변 나무

건물 주변 나무 밀도는 건물의 역할과 공간 크기를 고려한다.

## 일반 건물

소수의 나무와 작은 식생을 사용한다.

건물 Sprite를 과도하게 가리지 않는다.

## 병원

병원의 전면과 응급차 이동 경로를 반드시 확보한다.

가능하면 다음 영역 중심으로 배치한다.

```text
병원 측면
병원 후면
주차 공간 외곽
```

다음 위치를 가리지 않는다.

```text
병원 정문
구급차 접근로
도로
교차로
```

## 항구 / 산업지역

도심과 공원 지역보다 자연물 밀도를 낮춘다.

산업적인 분위기가 유지되어야 한다.

## 공원 인접 건물

공원과 건물의 녹지가 자연스럽게 이어지도록 나무 밀도를 조금 높일 수 있다.

---

# 14. 나무 반복감 방지

같은 나무 Prefab을 같은 간격으로 계속 복사한 느낌이 강하게 나지 않도록 한다.

가능한 경우 기존 나무 리소스를 확인하여 다음에 약간의 변화를 준다.

```text
간격
위치
종류
방향
크기
```

Scale을 변경해야 한다면 작은 범위만 사용한다.

예:

```text
0.9 ~ 1.1
```

정확한 값은 실제 Sprite 크기와 게임 화면을 보고 판단한다.

과도한 랜덤 크기는 사용하지 않는다.

---

# 15. 작은 식생 배치

수풀이나 작은 식생 리소스가 존재한다면 나무 사이의 빈 공간이나 공원 주변에 사용할 수 있다.

단, 모든 나무 아래에 기계적으로 배치하지 않는다.

권장 위치:

```text
공원 외곽
강변
나무 군집 사이
건물 사이 작은 녹지
도시 외곽
```

작은 식생은 보조 장식이며 나무보다 시각적 우선순위가 낮다.

---

# 16. 공원 구성

Maps.png의 특징 중 하나는 큰 빈 녹지를 단순한 잔디 공간으로 두지 않는 것이다.

현재 `NewGamePlay`에서 충분히 큰 빈 녹지 구역은 작은 공원 또는 중형 공원으로 구성한다.

공원은 기본적으로 다음 구조를 사용한다.

```text
녹지
+
나무
+
보행길
+
중앙 포인트 또는 여백
```

중앙 포인트는 기존 리소스가 있다면 사용할 수 있다.

예:

```text
분수
화단
작은 정원
광장
```

없는 리소스를 임의로 새 디자인해서 만들지 않는다.

---

# 17. 공원 크기 구분

모든 공원을 같은 크기와 형태로 만들지 않는다.

## 작은 공원

```text
나무 몇 그루
+
짧은 보행길
+
작은 중앙 공간
```

## 중형 공원

```text
여러 방향의 길
+
중앙 공간
+
주변 나무
+
식생
```

## 큰 녹지

강변이나 넓은 자연 구역에서 사용한다.

```text
산책로
+
나무 군집
+
넓은 녹지
+
불규칙한 자연 공간
```

---

# 18. 공원 내부 길

공원 내부 보행길은 복잡한 미로 형태로 만들지 않는다.

권장 형태:

```text
직선
L자
T자
십자
짧은 굴곡
```

공원 크기에 맞게 단순하고 읽기 쉬운 형태로 만든다.

---

# 19. 공원 길 연결

가능하면 공원 길은 기존 보도와 자연스럽게 이어지도록 한다.

권장 구조:

```text
Sidewalk
↓
Park Path
↓
Park
```

다음 구조는 피한다.

```text
길이 나무에서 갑자기 끝남
길이 건물 벽에서 끝남
길이 물에서 끝남
길이 차량 도로 중앙에서 끝남
```

---

# 20. 향후 Citizen AI 고려

현재 단계에서 Citizen AI를 구현하지 않는다.

다만 향후 시민 AI가 공원 길을 사용할 가능성이 있으므로 공원 길은 실제 사람이 걸을 수 있는 구조처럼 만든다.

이번 단계에서는 다음 시스템을 추가하지 않는다.

```text
Citizen AI
Sidewalk AI
Park Path AI
Pathfinding
Navigation Graph
```

시각적 구조만 준비한다.

---

# 21. 하천 꾸미기

현재 중앙 하천은 전체 맵에서 중요한 시각적 요소이다.

단순한 파란색 물줄기로만 보이지 않도록 주변 환경을 구성한다.

기본적인 시각 흐름은 다음과 같다.

```text
물
↓
돌 / 자연 경계
↓
잔디
↓
나무 / 식생 / 산책 공간
```

모든 구간을 동일하게 만들지는 않는다.

---

# 22. 하천 돌 배치

돌을 동일한 간격으로 일렬 배치하지 않는다.

나쁜 예:

```text
O O O O O O O O O O
```

좋은 방향:

```text
O   OO       O

   O     OOO

OO        O
```

약간의 군집과 빈 공간을 섞어 자연스럽게 만든다.

---

# 23. 하천 돌 밀도

하천 전체에 같은 밀도로 돌을 배치하지 않는다.

## 직선 구간

중간 밀도로 사용한다.

## 굴곡 구간

직선 구간보다 조금 많은 돌을 사용할 수 있다.

## 공원 인접 구간

다음 요소를 함께 조합할 수 있다.

```text
돌
나무
식생
녹지
산책로
```

## 다리 주변

돌 밀도를 줄인다.

다리가 자연물에 묻히지 않도록 한다.

---

# 24. 강변 나무

강 주변은 일반 도심보다 자연물 밀도를 높일 수 있다.

하지만 강 전체를 나무 벽으로 둘러싸지 않는다.

예:

```text
Tree Tree

        Tree

Tree          Tree Tree
```

나무 군집과 빈 공간을 함께 사용한다.

---

# 25. 강변 안전 영역

다음 구역은 나무, 돌, 식생으로 침범하지 않는다.

```text
다리
차량 도로
보도 통행 공간
교차로
건물 입구
병원 출입구
항구 진입로
```

다리의 시작점과 끝점 주변은 특히 가독성을 확보한다.

---

# 26. 도시 구역별 자연환경 밀도

전체 Scene에 동일한 장식 규칙을 적용하지 않는다.

지역별 특징을 만든다.

## 북쪽 도심

```text
정돈된 나무
작은 녹지
작은 공원
건물 주변 식생
```

전체적으로 정돈된 도시 분위기를 유지한다.

## 중앙 강변

```text
나무 밀도 높음
강변 산책 공간
돌
자연형 녹지
```

이번 자연환경 작업에서 가장 풍부하게 꾸밀 수 있는 지역이다.

## 남서 항구

```text
나무 적음
식생 적음
산업적인 분위기 유지
```

항구 시설이 자연물보다 우선적으로 보여야 한다.

## 남동 지역

```text
건물과 도로 중심
일부 정돈된 녹지
작은 나무 군집
```

## 도시 외곽

```text
나무 밀도 높음
식생 사용
도시 경계 역할
```

실제 세부 배치는 `Maps.png`와 현재 Scene을 비교해서 결정한다.

---

# 27. 빈 공간 유지

모든 공간을 꽉 채우지 않는다.

시각적으로 필요한 여백은 그대로 유지한다.

특히 다음 주변은 여백을 고려한다.

```text
큰 건물
병원
교차로
다리
항구
주요 도로
공원 중앙
```

# 34. GameObject 수 관리

단순한 장식 때문에 GameObject 수를 필요 이상으로 늘리지 않는다.

예를 들어 강변 돌을 표현하기 위해 수천 개의 개별 GameObject를 만드는 방식은 피한다.

가능하면 적은 오브젝트로 비슷한 시각적 결과를 만든다.

단, 성능 최적화를 이유로 기존 프로젝트를 크게 리팩터링하지 않는다.
