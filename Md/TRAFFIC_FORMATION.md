# 직선 도로의 엇갈린 차량 배치와 대열 해소

## 적용 동작

- 4·6차선 직선에서 같은 방향 차량을 다른 차로에 생성할 때, 옆 차량과 앞뒤 간격을 둔다. 차체 방향은 차로 접선을 유지한다. 차로 번호에 따른 거리 오프셋과 실제 차량 길이를 함께 검사하므로 버스와 승용차, 서로 다른 도로 타일의 경계에서도 가로로 겹치는 배치를 피한다.
- 같은 방향의 다른 차로 차량이 비슷한 속도와 앞뒤 위치로 나란히 달리면, 가속 여유가 있는 안쪽 차로 차량부터 한 대를 먼저 선택한다. 안쪽 차량이 막혔으면 여유 있는 다른 차량을 선택한다.
- 보정은 기본 순항 속도를 변경하지 않는 6초의 임시 목표 속도다. 기존 가속도로 부드럽게 접근하고, 기존 최대 생성 속도인 `차로 폭 × 3유닛/초`를 넘지 않는다. 차로별 보정 폭을 다르게 하여 후속 보정 차량이 다시 같은 속도의 대열을 만들 가능성을 낮춘다. 동일 차량의 재시도 간격은 게임 시간 기준 10초다.
- 앞차·플레이어 관측, 안전 간격, 제동 거리, 신호와 교차로 출구 예약은 보정 목표보다 우선한다. 가속을 결정한 프레임에도 기존 안전 속도 계산을 다시 적용한다.
- 정지·서행 대기열, 교차로 안과 접근 구간, 차로 변경 중인 차량, 사고로 물리 제어에 넘어간 차량과 픽업 도로는 대상에서 제외한다. 충분한 전방 직선이 없으면 보정을 시작하거나 유지하지 않는다.
- 보정 중인 차량이 먼저 간격을 벌릴 때까지 같은 대열의 동시 가속을 억제한다. 3개 차로에서는 앞선 보정 차량이 떨어져 나간 뒤 남은 대열을 순서대로 처리할 수 있다.

## 예상한 오류와 방지 방법

| 예상 문제 | 처리 |
| --- | --- |
| 차량을 비스듬히 생성해 차선 침범·충돌 발생 | 회전은 유지하고 차로상의 앞뒤 거리만 변경 |
| 다른 타일의 차량과 가로로 겹쳐 생성 | 타일 번호 대신 실제 위치·진행 방향·차체 길이로 비교 |
| 반대편 차량을 대열로 오인 | 같은 방향의 평행 직선 차로만 비교 |
| 여러 차량이 동시에 같은 속도로 가속 | 대열 내 우선 차량 선택, 진행 중인 보정 확인, 차로별 보정 폭 구분 |
| 앞차 추돌·신호 위반·픽업 방해 | 기존 안전 속도 계산 유지, 위험·정지·픽업·교차로·변경 구간 제외 |
| 가속·복귀의 급격한 반복 | 기존 가감속 적분과 보정 시간·재시도 대기 적용 |
| 풀 재사용 시 이전 속도 보정이 남음 | 재활성화 시 보정 시간·재시도 대기를 0으로 초기화 |
| 모든 차량 앞이 막혀 있어도 강제 가속 | 안전하게 가속할 후보가 없으면 기존 감속·대기 유지 |

## 변경 파일과 검증

- `RoadTrafficController`: 모든 생성 경로에 엇갈린 거리 후보와 다른 차로 간 앞뒤 간격 검사를 적용한다. 화면 밖 보충, 차량 수 상한과 주변 교통 우선 정책은 유지한다.
- `RoadTrafficSimulation`: 평행 대열 판정, 가속 후보 선택, 임시 목표 속도와 기존 안전 제한의 결합을 담당한다. 저수준 `TryAddVehicle` API는 테스트와 기존 호출 호환성을 위해 유지한다. 실제 게임 생성은 컨트롤러가 간격 검사를 수행한다.
- `RoadTrafficVehicle`: 비직렬화 런타임 상태에 보정 시간과 재시도 대기를 저장한다. 씬·프리팹·Inspector 필드는 변경하지 않는다.
- `TrafficFormationTests`: 4·6차선의 네 방향 회전, 타일 경계, 자유 차로 선택, 막힌 앞차, 정지 대열, 적색 신호, 교차로 접근, 차로 변경·사고 제어, 반대 방향, 기존 속도 상한, 순항 속도 보존과 풀 재사용을 검사한다. 실제 GamePlay 생성 검사에는 8개 미션 시드를 사용한다.

검증 환경은 Unity 6000.3.23f1, Editor/Standalone, Input System 1.20.0, URP 17.3.0, Test Framework 1.6.0이다. 사용자가 연 원본 에디터를 종료하지 않고 `.utmp/WaitingValidation` 복사본에서 실행하며, 변경 소스가 원본과 같은지 확인한다.

테스트 결과는 `.utmp/traffic-formation-before.xml`, `.utmp/traffic-formation-regression.xml`에 보관한다. 기존 `TrafficCoverageTests`, `TrafficPickupTests`, `MissionRoadGenerationTests`도 함께 실행해 이전 교통 보충과 픽업·도로 생성 회귀를 검사한다.

2026-10-25 최종 결과: 컴파일 성공, 관련 자동 검사 **59개 모두 통과**(실패·건너뜀 0개, 약 46.8초). 새 생성·대열·안전 검사 34개와 기존 교통 보충·픽업·도로 생성 검사 25개를 포함한다. 수정 전 25개 검사에서는 가로 대열 생성·유지와 관련된 19개가 실패했고, 수정 후 해당 조건도 통과했다. 최종 실행에서 C# 컴파일 오류, NullReferenceException 및 MissingReferenceException은 관찰되지 않았다. 변경 소스와 검증 복사본의 일치 및 `git diff --check` 통과를 확인했다.

키·터치 조작으로 느끼는 추월 여유, 화면의 시각적 검수, 모바일 WebGL 실행과 성능 측정은 별도 확인이 필요하다. 모든 차로가 정체하거나 신호로 막힌 상황까지 항상 추월할 수 있음을 보장하지 않는다.

## 수동 확인 순서

1. Play Mode를 종료하고 컴파일을 기다린 뒤 대기 씬에서 수락·출동한다. 추가 Inspector 설정은 필요 없다.
2. 4차선과 6차선의 긴 직선을 각각 주행한다. 같은 방향 차량이 앞뒤로 엇갈려 생성되고, 차체는 차로 방향을 유지해야 한다.
3. 옆 차로 차량들이 비슷한 속도로 나란히 달릴 때 여유 있는 한 대가 서서히 앞서가며 틈이 생기는지 확인한다.
4. 신호 대기열과 막힌 앞차·픽업 구간에서는 감속·정지가 우선인지 확인한다.
5. 병원 후송을 마치고 다시 출동해 이전 차량의 보정 상태가 새 차량에 남지 않는지 확인한다.
