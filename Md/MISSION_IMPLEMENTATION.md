# 미션 대기 → 수락 → 시드 → 맵 생성

## Unity에서 한 번 연결하기

현재 코드와 설정 메뉴는 작성되어 있지만 씬에 저장하는 작업은 아직 실행하지 않았다. `AGENTS.md`의 `UNITY_PATH`가 TODO이므로 이번 작업에서 Unity를 실행하거나 실행 파일을 찾지 않았다.

1. Unity **6000.3.23f1**에서 프로젝트를 열고 새 스크립트 import와 컴파일이 끝날 때까지 기다린다.
2. **Assets/Scenes/GamePlay.unity**를 연다. 현재 씬의 사용자 편집을 유지한다.
3. Play 모드 밖에서 **CodeBlue Rush → Set Up GamePlay Missions**를 실행한다.
4. Console에 설정 완료 메시지가 표시되면 **현재 GamePlay 씬만 저장**한다. 설정은 하나의 Undo 그룹으로 되돌릴 수 있다.
5. Play 모드에서 아래 시나리오를 확인한다.

메뉴는 기존 `Canvas/MissionWait` 또는 `Canvas/MissionWait_Button` Image에 Button을 추가한다. 기존 이름, 위치, 크기와 Image는 보존한다. 새 브리핑과 상태 표시는 `Canvas/MissionSafeArea` 아래에 생성하고 화면 안전 영역을 반영한다. 운전 설정이 아직 저장되지 않았으면 기존 `GamePlayDrivingSetup.ConfigureScene`을 같은 Undo 그룹 안에서 실행한다.

`MissionSystem`이 이미 존재하면 메뉴는 기존 설정을 덮어쓰지 않는다. 이후에는 Inspector에서 조정한다. 실패하면 이번 메뉴 실행의 변경만 Undo로 취소하며, 다른 씬·프리팹·패키지·프로젝트 설정을 저장하지 않는다.

## 동작

- 시작 시 미션 버튼을 숨긴다. 실제 시간 5초 후 버튼과 오른쪽 위 빨간 Image의 `!`를 표시한다.
- 버튼을 누르면 브리핑과 수락/거절 버튼을 표시하고 알림을 지운다.
- 거절하면 수락 판정과 시드 생성 없이 다시 5초를 기다린다. 다음 제안은 새 요청 번호를 사용한다.
- 수락하면 8자리 시드를 생성하고 맵을 연결한다. 맵 준비가 끝난 뒤 `IsMissionActive`, `CurrentSeed`, `OnMissionAccepted`를 공개한다.
- 진행 중에는 미션 버튼을 숨긴다. 시드는 상단 상태 텍스트와 MissionController의 읽기 전용 프로퍼티로 확인할 수 있다.
- 시작 구역 안쪽으로 구급차를 Rigidbody2D 위치/회전 API로 옮기고, 마지막 직선 구역 안쪽에 `도착` 표시를 배치한다.
- 대기·브리핑·준비 중에는 운전 입력을 비운다. 맵 준비 완료 후 조작을 허용하며 이전에 누르고 있던 키는 한 번 놓아야 적용된다.
- 맵 구역은 종류별로 풀에 보관하고 다음 수락 때 재사용한다. 기존 `Road_T_2Lane_0` 미리보기는 첫 생성 성공 후 런타임에서 숨긴다.
- 미션 관리자 비활성화 시 버튼 리스너와 대기 코루틴을 정리한다. 대기 상태로 재활성화하면 5초를 다시 센다.

브리핑은 현재 구현 범위에 맞춘 임시 출동 안내 문구다. 환자 픽업·네비게이션 UI·구출 컷신·병원 후송·결과는 이 단계에 포함하지 않았다. `도착`은 마지막 구역의 표시이며, 자동 도착 판정이나 미션 완료를 발생시키지 않는다. 후속 결과 시스템은 `MissionController.CompleteMission()`을 호출해 다음 5초 대기를 시작할 수 있다. 다음 맵은 그다음 제안을 수락할 때 생성된다.

## 확정한 시드 규칙

자리 번호는 **오른쪽부터** 읽는다. `12345678`의 1번째 자리는 8, 8번째 자리는 1이다.

| 자리 | 규칙 |
| --- | --- |
| 1 | 0~2: 2차선, 3~5: 4차선, 6~9: 6차선 직선 |
| 2 | 시작 직선의 개수, 1~9 |
| 3 | 같은 차선 Cross. 0~3 직진, 4~6 좌회전, 7~9 우회전 |
| 4 | Cross 출구 직선의 개수, 1~9 |
| 5 | 같은 차선 일반 T. 0~3 직진, 4~6 좌회전, 7~9 우회전 |
| 6 | 일반 T 출구 직선의 개수, 1~9 |
| 7 | 0~3: 같은 차선 Cross에서 직진. 4~6: T에서 좌회전. 7~9: 혼합 차선 T에서 우회전 |
| 8 | 마지막 출구 직선의 개수, 1~9 |

7번째 자리의 4~6 분기는 2차선 → `T2Lane`, 4차선 → `TV4LaneH2Lane`, 6차선 → `T6Lane`이다. 7~9 분기는 2차선 → `TV2LaneH4Lane`, 4차선 → `TV4LaneH6Lane`, 6차선 → `TV6LaneH4Lane`이다. 혼합 T를 지난 직선은 실제 출구의 차선 수를 사용한다.

일반 T의 직진은 프리팹을 회전하여 양쪽 연결부를 통과하도록 배치한다. 가능한 회전은 0, 90, 180, 270도 순서로 검사하므로 같은 시드와 카탈로그는 항상 같은 배치를 만든다. 기존 `RoadPrefab`의 방향별 차선 수와 `TryGetConnectionPosition`을 사용한다.

2·4·6·8번째 자리에 0이 없는 시드만 생성한다. **10203040은 반복 횟수가 4·3·2·1이므로 허용된다.** 선택/방향 자리의 0은 허용한다. 경로가 이전 구역을 덮는 시드는 후보에서 제외하고 다시 뽑는다. 최대 256번 시도한 뒤에도 유효한 후보가 없으면 오류를 표시하고 미션 관리자를 비활성화한다. 외부에서 지정한 잘못된 시드는 다른 맵으로 바꾸지 않고 실패한다.

현재 13개 도로는 중심 pivot, 스케일 1, 동일한 12.54 × 12.54 월드 유닛의 정사각 구역이다. 다른 크기나 연결 규격을 쓰려면 생성 규칙도 함께 확장해야 한다. 구역은 7~39개이며, 교차로에서 선택한 하나의 이동 경로만 확장한다.

## 검증(Verification)

- 새 런타임/에디터 스크립트를 기존 생성 프로젝트의 참조로 복사본 프로젝트에서 .NET 컴파일했다. 원본 `.csproj`와 `Library`, `Temp`는 편집하지 않는다. 이는 Unity 컴파일이나 WebGL 빌드 검증이 아니다.
- `Tools/VerifyMissionRules.ps1`은 Unity 없이 실제 `MissionSeedRules.cs`, `RoadIndex.cs`를 C# 9로 컴파일하여 검사한다. 원본 13개 프리팹의 방향별 차선 정보를 읽고 전체 숫자 분기 조합, 100,000개 고정 난수 표본, 재현성, 반복 횟수, 차선 연결, 겹침 거부를 검사한다.
- Unity 컴파일/PlayMode 테스트/씬 메뉴 실행/화면 배치/WebGL 빌드는 **미실행**이다. `UNITY_PATH`가 TODO이므로 실제 에디터에서 확인해야 한다. 한글 폰트와 TMP 설정/셰이더 파일은 읽기 전용으로 확인했으며, 실제 글리프 렌더링은 아직 확인하지 않았다.

2026-10-12 최종 결과: .NET 런타임/에디터 컴파일 경고 0개, 오류 0개. 순수 규칙 검사 **11,740,573개 어설션 통과**, 숫자 분기 조합 10,000개, 난수 표본 100,000개 중 유효 경로 98,905개 및 겹침 거부 1,095개. 이는 UI 클릭, 코루틴 시간, Rigidbody 순간이동, 풀 활성화 콜백의 런타임 검증을 포함하지 않는다. 변경한 운전 입력 파일의 `git diff --check`는 통과했다. 저장소 전체 검사에는 기존 사용자 씬 편집의 `m_Name:` 줄 후행 공백이 남아 있으며 이번 작업에서 수정하지 않았다.

순수 규칙 검사를 다시 실행하려면 프로젝트 루트의 PowerShell에서 `& ./Tools/VerifyMissionRules.ps1`을 실행한다. 출력물은 `.utmp/mission-rules-<고유값>`에 생성한다.

## 수동 플레이 모드 확인 — 미실행

1. 시작 직후 버튼 없음 → 약 5초 뒤 버튼과 `!` → 클릭 후 브리핑과 수락/거절 표시.
2. 거절 후 버튼이 숨겨지고, 5초 뒤 새 요청 번호가 표시되며 수락/시드/맵 생성이 발생하지 않는지 확인.
3. 수락을 빠르게 반복 클릭해도 한 번만 생성되고, 표시된 시드가 8자리이며 짝수 자리에 0이 없는지 확인.
4. 맵 경계가 맞물리고, T 회전 및 혼합 차선 출구가 이어지며, 마지막 도로에 도착 표시가 있는지 확인.
5. 수락 후 버튼이 숨겨지고, 맵 생성 전 눌렀던 키·페달 입력이 남지 않는지 확인.
6. 미션 관리자를 대기 중 비활성화/재활성화하고, 씬 재진입 및 반복 Play에서 중복 알림/리스너가 없는지 확인. 현재 설정은 Domain Reload 꺼짐, Scene Reload 켜짐이다.
7. timeScale 0에서 제안 대기는 계속 진행하고 운전 입력은 차단되는지 확인.
8. 다양한 세로 비율과 모바일 안전 영역에서 브리핑·버튼·시드 텍스트 및 한글 폰트 표시를 확인.
9. 이후 결과 시스템에서 CompleteMission을 연결한 뒤 다음 수락 때 구역 풀 재사용과 이전 도착 표시 이동을 확인.

## AGENTS.md 제안

`UNITY_PATH`, 비동기 스타일, 배치 타임아웃 TODO는 그대로 두었다. `GAME_REMAKE_SPEC.md`는 WebGL/모바일 브라우저를 지정하지만 AGENTS.md의 대상 정책은 PC/Standalone이므로 후속 빌드 작업 전에 문서 정리가 필요하다. 실제 저장된 scriptingBackend 매핑에는 Android: 0만 있으며 Standalone 백엔드는 알 수 없다. 이 문서 작성은 AGENTS.md 수정이나 대상 플랫폼 설정 변경을 수행한 것이 아니다.

순간이동과 지속 이동은 다른 동작이므로 시작 위치에는 Rigidbody2D 위치 설정을 사용한다. 관련 엔진 계약은 [Unity 6000.3 Rigidbody 2D 문서](https://docs.unity.com/en-us/engine/6000.3/manual/unity2d/2d-physics/rigidbody-2d/introduction-to-rigidbody-2d)를 참고한다.
