# T자 도로의 세로 2차로 우회전 추가

대상은 `Road_T_6Lane`과 `Road_T_V6Lane_H4Lane`이다. 차로 번호는 기존 시스템과 같이 중앙선 쪽부터 1번이다. 원본 Prefab 방향에서 남쪽 세로 진입 2차로 → 동쪽 가로 출구 2차로의 우회전 곡선을 추가했다. 회전 배치에서도 도로의 로컬 방향에 맞춰 동일하게 회전한다.

두 Prefab의 차로 수 조합(북쪽 닫힘, 남쪽 왕복 6, 동서 왕복 4 또는 6)이 현 13종 중 이 두 도로에만 해당함을 확인했다. 기존 데이터로 생성하므로 `.prefab`/`.meta` 변경이나 새 직렬화 필드 없이 적용한다. 그 외 도로의 차로 정책은 유지한다. 유턴은 추가하지 않았다.

기존 경로 뒤에 추가해 해당 도로 안에서 기존 경로 Id를 유지한다. 경로는 기존 진입/출발 차로와 연결되며 후송 그래프에도 포함된다. 전체 맵의 Id는 스냅숏 내부 식별자이므로 새 그래프 생성 때 소비자가 다시 획득해야 한다.

혼합 6→4차로 도로에서는 세로 2차로와 기존 세로 3차로가 같은 출구 2차로로 합류한다. 네트워크의 `Conflicts`가 이 합류를 양방향으로 제공함을 검사했다. 실제 차량의 양보/정체 제어는 기존 계획대로 향후 AI의 역할이다.

## 검증(Verification)

- 실제 13종 Prefab 데이터와 변경된 런타임 코드를 이용한 근사 .NET 검사: **165,805개 조건 통과**, 156개 회전·경계 사례, 100개 픽업/후송 시드 쌍.
- 두 대상의 네 회전에서 진입 2차로 → 우회전 곡선 → 출발 2차로 → 다음 직선 도로 2차로의 탐색/위치/접선을 검사했다. 혼합 도로의 합류 충돌 정보도 검사했다.
- 전체 런타임 근사 .NET 빌드: 오류 0개. 기존 직렬화 필드에 대한 CS0649 경고 10개이며 이 작업에서 해당 필드를 변경하지 않았다.
- Unity **6000.3.23f1**의 작업 소유 격리 프로젝트에서 실제 두 Prefab을 로드해 검증: **60개 조건 통과**, 2종×4회전. 정상 종료 코드 0. `unity-verification.json`, `unity-verify.log` 참조.
- 원본 도로 이미지에 변경된 실제 경로 계산 결과를 겹친 `lane-paths-review.png`를 시각 검토했다. Game View 캡처는 아니다.
- Unity 검증 동안 원본 보호 파일의 해시 변경 없음. 원본 프로젝트의 사용자 에디터를 종료하거나 씬/프리팹/메타데이터를 재저장하지 않았다.
- Play Mode 차량 주행 및 플레이어 빌드는 실행하지 않았다.

원본에서 변경한 런타임 파일은 `Assets/Scripts/Traffic/RoadLaneLayout.cs` 한 개다. 기존 공개 API와 직렬화 필드, enum 값, 어셈블리 구조는 유지했다. 새 런타임 스크립트/메타데이터 생성은 없다. 검증용 Editor 스크립트는 격리 복사본에만 import했다.

수동 확인: Unity에서 스크립트 컴파일이 끝난 뒤 두 Prefab을 선택하고 Gizmos를 확인한다. 기존 Play 세션에서 생성된 그래프를 사용 중이면 맵을 다시 생성해 최신 연결을 획득한다.
