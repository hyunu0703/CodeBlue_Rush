# 픽업·내비게이션·구출·병원 후송 구현

## 변경 사항

- `MissionController`: 미션 수락 → 픽업 이동 → 구출 → 후송 → 병원 도착 흐름을 연결했다. 도착 감지는 차량 중심의 이동 선분과 반경 0.85 월드 유닛으로 판정한다. 컷신 동안 입력을 비우고 기존 Rigidbody2D constraints를 보관한 뒤 FreezeAll로 고정하며, 완료/중단 시 원래 제약으로 복구한다.
- `MissionMapGenerator`: 기존 시드 도로 프리팹/풀을 재사용한다. 픽업은 기존 마지막 도착 지점이다. 후송은 기존 마지막 구역의 출구에 새 시드 도로를 연결하며 구급차 위치와 픽업 도로를 유지한다. 현재 단계의 연결 순서로 내비게이션 경로를 제공한다. 다음 미션 수락에서만 두 단계의 도로를 풀에 반환하고 새 맵을 만든다.
- `MissionSeedRules`: 픽업과 후송 사이의 차선, 방향, 정수 격자 겹침을 검사한다. 같은 픽업 시드에서 같은 후송 후보 순서를 사용한다. 수락 전에는 후송 가능성을 검증하고, 게임 상태의 `TransportSeed`는 구출 완료 뒤에만 확정한다. 출구가 막힌 픽업 시드는 제외한다. 후보 탐색은 픽업 256회, 후송 1024회로 제한된다.
- `MissionNavigationGraphic`: 도로는 연한 흰색, 안내 경로는 하늘색, 차량은 초록색 원과 흰색 `^`다. 차량은 하단 중앙에 고정하고 차량 상대 위치와 카메라의 실제 회전으로 지도를 갱신한다. RectMask2D로 패널 경계에서 잘라낸다. 표시 폭 40 월드 유닛, 도로/경로 두께 8/4 Canvas 픽셀이 기본값이다.
- `PatientRescueCutscene`: 대원 두 명과 환자 한 명의 임시 스프라이트를 런타임에 생성한다. 0.7초 대기 → 2초 동안 차량 콜라이더의 후면으로 이동 → 이미지 숨김 → 픽업 완료 순서다. 일시정지 중에는 진행하지 않는다. 코루틴은 미션 관리자가 소유하고, 이미지·텍스처는 컷신 컴포넌트가 생성/해제한다.

기존 씬에는 NavigationPanel이 저장되어 있지 않았다. Canvas 아래 기존 이름의 패널이 있거나 Inspector 참조가 지정되어 있으면 재사용하고, 없으면 미션 Safe Area 우상단에 160×160 패널을 런타임으로 생성한다. 새 이미지와 패널은 Play 모드의 일시적 오브젝트이며 씬 저장은 필요하지 않다. 병원 위치는 후송 마지막 직선 도로의 도착 표시이며 `병원` 텍스트로 표시한다. 별도 결과 팝업은 이번 요청 범위에 포함하지 않았다. 병원 도착 시 완료 상태를 표시하고 기존 5초 미션 대기 흐름을 재사용한다.

## 검증

- 작업 시작 Git 상태: 변경 없음. commit/push/브랜치/stash 작업 없음.
- 감지 환경: Unity `6000.3.23f1`, Input System `1.20.0`, uGUI `2.0.0`과 포함 TMP, C# 9, 도메인 리로드 비활성/씬 리로드 활성. Assets 아래 asmdef/asmref가 없어 변경/신규 런타임 코드는 기존 `Assembly-CSharp`에 속한다.
- 생성된 csproj의 컴파일/참조 정보를 별도 출력 폴더로 복사하고 신규 스크립트 두 개를 추가한 .NET 근사 컴파일: **성공, 경고 0, 오류 0**. 원본 생성 csproj, Library, Temp는 편집하지 않았다. 원본 csproj는 WebGL을 나타내며, 의도된 PC 대상이나 실제 Unity 빌드 성공을 입증하지 않는다. Standalone 백엔드는 설정 매핑에 없어서 알 수 없음이다.
- 실제 `MissionSeedRules.cs`와 `RoadIndex.cs`를 컴파일한 .NET 계획 검사: **고정 사례 4개 + 유효 픽업/후송 조합 10,000개 통과**. 직진 좌표, 차선 불일치, 잘못된 시드, 출구가 막힌 `89279899`를 확인했다. 4방향, 2/4/6차선, 연결 칸 인접성, 방향/차선 연속성, 기존 도로 겹침 방지, 모든 계획 필드의 재현성을 검사했다.
- 표본: 후송 후보 최대 453회, 겹침 후보 1,491개 거부, 후송 불가능한 픽업 후보 54개 거부. 이는 표본 결과이며 모든 시드의 성공 보장이 아니다. 실행 코드는 탐색 실패 시 이동 단계를 시작하지 않는다.
- `git diff --check`: 공백 오류 없음. 최종 diff와 추가 파일을 검토했다.
- **Unity 컴파일/import/EditMode·PlayMode 테스트/플랫폼 빌드 미실행**: AGENTS.md의 `UNITY_PATH`가 TODO이며 사용자 요청 없이 실행 파일을 탐색하지 않는 규칙에 따랐다. 실제 UI 클리핑·이미지 외형·물리/생명주기/입력 동작은 Unity에서 검증되지 않았다.

계획 검사는 `PlannerChecks.cs`이며 `dotnet run --project output/mission-loop-20261012/PlannerCheck.csproj`로 다시 실행할 수 있다. .NET용 출력 프로젝트는 Unity 어셈블리나 테스트 어셈블리를 변경하지 않는다.

## 수동 에디터 작업 및 플레이 모드 확인 — 미실행

1. Unity 6000.3.23f1에서 import와 컴파일 완료를 확인한다. 새 스크립트의 메타데이터는 현재 미생성이다. 다음 두 파일의 `.meta` 및 새 `_Project/Scripts/UI`, `_Project/Scripts/Missions` 폴더 계층의 `.meta`를 Unity가 생성하게 하고 함께 유지한다.
   - `Assets/_Project/Scripts/UI/MissionNavigationGraphic.cs.meta`
   - `Assets/_Project/Scripts/Missions/PatientRescueCutscene.cs.meta`
2. 저장된 `Assets/Scenes/GamePlay.unity` 또는 Start에서 시작해 미션 수락 후 마지막 `픽업` 지점으로 이동한다. 초록 차량 원/꺾쇠가 고정되고, 교차로에서 도로와 하늘색 경로가 카메라 회전과 일치하며 패널 밖에 그려지지 않는지 확인한다.
3. 도착 시 조작과 차량 이동이 멈추고 대원 2명/환자 1명이 기다렸다가 차량 뒤로 이동하는지 확인한다. 이미지가 사라지기 전에는 `IsPatientPickedUp`이 false, `TransportSeed`가 0이어야 한다. 사라진 뒤에는 픽업 완료 및 후송 시드가 표시되고 입력이 복구되어야 한다.
4. 구급차 위치가 유지되고 기존 도로의 출구에 후송 도로가 차선 수를 맞춰 이어지는지 확인한다. 마지막 `병원` 지점에서 완료 표시/정지를 확인한다. 다음 미션 수락 전에는 새 맵이 생성되지 않아야 한다.
5. 컷신 중 `MissionController` 비활성/재활성화, 컷신 중 timeScale=0/복구, 후송 중 비활성/재활성화, 입력을 누른 상태로 컷신 완료, 반복 Play와 다음 미션의 풀 재사용을 확인한다. 중단된 컷신은 픽업 완료로 처리하지 않고 같은 픽업 단계로 복귀해야 한다.

## API / 직렬화 변경

기존 public 메서드/Configure 시그니처, 타입·파일명, namespace와 직렬화 필드 이름/타입을 유지했다. `IsMissionActive`는 구출/후송까지 포함하고, 운전 허용은 이동 단계로 별도 제한한다. `TransportSeed`, `IsPatientPickedUp`, 맵 읽기 전용 목록, 목적지 이름 변경 및 후송 계획/연장 API를 추가했다. 도착 반경과 선택적 표시 참조 필드는 추가만 했다. 기존 private 상태 enum 값은 유지하고 구출/후송을 뒤에 추가했다.

C# 호출부와 텍스트 씬/프리팹/에셋의 UnityEvent·AnimationEvent·문자열 호출을 검색했다. 알려진 호환 진입점과 기존 이벤트를 유지했다. 외부/동적 문자열/바이너리 호출은 검증 안 됨이다. asmdef/asmref, 패키지, ProjectSettings, 씬/프리팹/직렬화 에셋 및 `.meta` 직접 변경은 없다.

## 내비게이션 조사

[카카오내비 공식 서비스 소개](https://www.kakaomobility.com/service-navi)의 지도/경로 안내 구성과 [카카오모빌리티 고객지원](https://service.kakaomobility.com/cs/faqs/content/?category=9)을 조사했다. 이번 구현의 초록색 차량, 연한 흰색 도로, 하늘색 경로, 하단 중앙 고정과 카메라 동기화 정책은 사용자가 지정한 요구사항을 따른다. 상용 내비게이션 SDK/외부 지도는 도입하지 않았다.

## AGENTS.md 제안
