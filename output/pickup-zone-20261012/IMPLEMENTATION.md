# 오른쪽 차선 픽업 영역과 도보 대기 배치

## 카메라 확대 롤백 — 2026-10-12

사용자 요청에 따라 아래 최초 구현의 카메라 범위 1/3 축소 처리를 제거했다. `MissionController`는 카메라 Size를 변경하지 않으며 현재 GamePlay 씬에 저장된 Orthographic Size 5를 그대로 사용한다. 픽업 영역과 인물 배치는 유지한다. 추가한 카메라 비율 필드는 Assets의 씬/프리팹이나 다른 코드에서 참조되지 않음을 검색한 뒤 제거했다. 아래 카메라 1.667 적용 설명과 확인 단계는 최초 구현 기록이며 현재에는 적용되지 않는다. Play를 종료하고 재컴파일한 뒤 재실행하여 Size 5와 기존 시야를 확인한다. Unity Play 검증은 미실행이다.

## 변경 사항

- 최종 도로 진행 방향을 기준으로 가장 오른쪽 차선 중앙을 픽업 장소로 지정한다. 2/4/6차선의 차선 폭과 도보 폭은 기존 도로 제작 스크립트의 `84.6px / 64px`, 원본 `1254px`, Sprite PPU `100` 규격을 확인하여 계산한다. 북쪽뿐 아니라 동/남/서쪽 도로에서도 진행 방향의 오른쪽을 사용한다.
- 노란색 `#FFFF00` 외곽선의 안쪽 크기는 구급차 Sprite 경계와 BoxCollider2D 경계를 합친 크기에 양옆/앞뒤 각각 0.08 월드 유닛을 더한다. 선 두께는 0.025 월드 유닛이다. 현재 차량 크기 기준 안쪽은 약 0.728×1.104이며, 선 바깥까지 포함한 폭은 약 0.778로 차선 폭 0.846 안에 들어간다. 실제 차량 크기를 실행 시 다시 읽는다. 영역이 차선보다 크면 미션 시작을 중단하고 설정 오류를 표시한다.
- 픽업 감지는 차량 이미지와 콜라이더 전체가 사각형 안에 들어왔을 때 시작한다. 차량의 물리 위치와 상대 회전을 반영하므로 앞부분만 진입하거나 비스듬히 돌출된 상태는 완료되지 않는다. 병원에는 기존 반경/이동 선분 감지를 유지한다.
- 노란 테두리는 구출 중 유지되고 이미지가 모두 사라져 픽업이 완료될 때 숨긴다. 컴포넌트 비활성화/미션 종료에서도 숨기며, 중단 후 재활성화하면 같은 픽업 장소에 복원한다. 기존 픽업 텍스트는 사각형이 차량을 가리지 않도록 빈 문자열로 바꾼다.
- 구급대원 2명과 환자 1명은 인접한 오른쪽 도보 중앙에 세로 한 줄로 대기한다. 원본 인물 크기는 그대로 사용하며 인물 중심 간격은 높이의 1.15배다. 컷신 이동 중 대형 간격을 좁혀 세 이미지가 모두 차량 후면 지점에 도착한 다음 숨긴다.
- 사용자의 확인에 따라 카메라가 보여 주는 월드 범위를 가로·세로 각각 1/3로 축소한다. 현재 저장된 Orthographic Size 5를 기준으로 Play 시작 시 약 1.666667을 적용한다. 재활성화/다음 미션에서 중복 적용하지 않는다. 런타임 적용이며 원본 씬 카메라의 저장값은 5다. 다른 시스템이 카메라 값을 바꾸지 않았다면 미션 관리자 제거 시 자신이 적용한 값을 복구한다.
- 실제 픽업 차선 지점까지 마지막 안내 경로도 이어지도록 갱신한다. 기존 후송 시드 연결과 도로 풀링을 계속 사용한다.

## 검증

- .NET 근사 컴파일: 경고 0개, 오류 0개. 생성된 프로젝트의 Unity 6000.3.23f1 참조와 C# 9 설정을 복사한 출력 프로젝트로 확인한다.
- 실제 `PatientRescueCutscene.cs`의 `PickupParkingGeometry.ContainsVehicle` 함수를 컴파일하여 **12개 사각형 판정 검사 통과**: 중앙, 가장자리 접촉, 부분 진입, 앞쪽 돌출, 90/45/180/5도 회전, 잘못된 크기/각도.
- 변경 코드의 정적 검토와 대상 파일 `git diff --check`: 공백 오류 없음.
- Unity 컴파일/import/PlayMode/플랫폼 빌드 미실행: AGENTS.md의 UNITY_PATH가 TODO이므로 실행 파일을 탐색하거나 Unity를 실행하지 않았다. 실제 원근, 선의 표시, 차량 주차, 도보 배치, 컷신 및 입력 동작은 Unity에서 검증이 필요하다.
- 시작 시 존재하던 `GamePlay.unity`, 폰트 에셋, 이전 미션/내비게이션 변경과 Unity가 이미 생성한 메타데이터를 보존했다. 이번 수정은 기존 C# 3개에 한정한다. 신규 Assets 스크립트와 추가 수동 메타데이터 작업은 없다.

## Play 모드 확인 — 미실행

1. Play를 종료하고 Unity 재컴파일을 기다린 뒤 다시 실행한다. Main Camera의 실행 중 Orthographic Size가 약 1.667인지 확인한다.
2. 미션을 수락하고 마지막 도로의 오른쪽 끝 차선에 있는 노란 사각형으로 이동한다. 세 인물이 옆 도보 안에 세로 한 줄로 보이는지 확인한다.
3. 차량 앞부분만 진입했을 때와 비스듬히 선 밖으로 돌출됐을 때에는 컷신이 시작되지 않아야 한다. 차량 전체가 안에 들어오면 조작이 잠기고 컷신이 한 번만 시작되어야 한다.
4. 컷신 중 노란 테두리가 유지되고, 세 인물이 차량 뒤로 모인 뒤 사라질 때 테두리도 사라져야 한다. 이후 후송 경로 생성과 조작 복구를 확인한다.
5. 구출 중 비활성화/재활성화, 일시정지/복구, 다음 미션, 동/남/서 방향으로 끝나는 시드를 확인한다. 카메라 확대가 누적되지 않고 도로의 주행 방향에 맞는 오른쪽 차선/도보가 선택되어야 한다.

## API / 직렬화 및 정책

기존 public 시그니처와 필드 이름/타입을 유지했다. 픽업 배치/주차 크기/감지 API와 미션 카메라 비율, 컷신 여백/선 두께의 직렬화 필드를 추가했다. `ShowPickup` 호출부는 새 도보 위치와 도로 방향을 전달하도록 모두 수정했다. asmdef/asmref, Packages, ProjectSettings, 씬/프리팹/에셋, `.meta` 직접 편집은 없다. 외부/동적/바이너리 호출과 Unity 직렬화 결과는 검증 안 됨이다.

AGENTS.md는 편집하지 않았다. UNITY_PATH, 배치 타임아웃, 비동기 스타일 TODO는 기존대로 남아 있다. 기존 코루틴 스타일을 사용한다. 검증 소스는 `GeometryChecks.cs`이며 `dotnet run --project output/pickup-zone-20261012/GeometryCheck.csproj`로 다시 실행할 수 있다.
